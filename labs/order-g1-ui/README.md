# 双框架业务：React 提交，Vue 列表

用户端是 React 表单，管理端是 Vue 列表。两边都要能看到加载、空数据、成功和失败。请求失败后，React 保留商品和幂等键，Vue 保留筛选词。

React 用哈希路由打开「查看已提交」，路由参数是订单号，另有自己的「已看到」状态。Vue 用路径 `/draft` 打开补记表单，字段是商品标识和备注，不是把 React 的幂等键改写成 Vue。组件怎么挂上测试，读公开课 `vue-test-utils-mount`。

订单数据来自 `labs/order-g1g2` 的 MySQL。本目录的测试用替身接口，不启动数据库。页面开发服务器把 `/orders` 转到 `http://127.0.0.1:8080`。

禁用提交按钮只发生在请求进行中。这不能保证库存只减一次。

## 核对

```bash
cd labs/order-g1-ui
npm test
npx tsc --noEmit
npm run e2e
```

`npm test` 不跑浏览器。`npm run e2e` 用 Playwright 打开 `http://127.0.0.1:5191/`。手工查看仍用 `npm run dev`，地址是 `http://127.0.0.1:5176/`。这条浏览器回归不在 `labs/run-regression.sh` 里。

要同时打开页面和数据库时，先在 `labs/order-g1g2` 按那里的说明启动 MySQL 和服务，再执行：

```bash
npm run dev
```

浏览器打开 `http://127.0.0.1:5176/`。服务没启动时，提交显示「网络未达」，商品和幂等键还在；管理端显示「读取失败。」

## 评分边界

- React：失败后商品和幂等键还在，成功后幂等键也还在，便于用同一键再提交。`not-owner` 同样保留这两项。提交过程中按钮不可点。哈希路由 `/sent/4` 显示「路由订单 4」，按钮可以从「标成已看到」变成「已看到」。
- Vue：空列表、有数据、读取失败各自有一句说明。`not-owner` 会显示这个类型。失败后筛选词还在，已经读到的订单不消失。`/draft` 是另一张表单：商品标识或备注为空时显示「还没写全。」，记下之后这两个字段还在。
- 浏览器回归覆盖 sold-out 后保留输入、React 路由和 Vue 补记。这一组仍没有 CI、OIDC 和上传。
