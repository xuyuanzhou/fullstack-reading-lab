## 前端路线：Vue 3

### 01 组合式 API 与选项式 API 如何组织一个复杂组件

- 状态：**已核验并发布**（`vue-composition-options`）。原件定位：Vue 资料第 1–10 页，主题 1。
- 学习目标：把一个同时含表单、请求与弹窗状态的组件分别按“选项”与“功能”拆开，观察阅读和复用成本。
- 暂定解释：两套 API 的主要差异应从逻辑组织、复用、类型推断和团队约束一起分析；避免宣称其中一套在任何项目都更好。
- 实验：实现相同行为的两个小组件，比较某一功能涉及多少处代码、抽取复用逻辑时需要移动哪些依赖。
- 待查证：Vue 当前对 Options API 与 Composition API 的定位、`setup` 和组合式函数的边界；原件有关“全部问题都能解决”的绝对化说法。

### 02 Vue 3 设计目标与性能指标

- 状态：**已核验并发布**（`vue-design-goals-proxy`；树摇「更快」另见 `vue-tree-shake-faster`）。原件定位：Vue 资料第 10–16、39–44 页。
- 学习目标：把“更快”拆成首屏、更新、包体与内存等可测量指标。
- 暂定解释：编译器和运行时都可能参与优化；性能结论应指定基准、版本和组件形态。
- 实验：同一交互记录构建体积和 Performance 时间线，保存测试环境、生产构建配置与重复测量结果。
- 待查证：静态提升、补丁标记、树摇等术语对应的准确实现与版本；资料中的性能百分比是否有可复现来源。

### 03 Modal 组件的接口与交互边界

- 状态：**已核验并发布**（`vue-modal-programmatic`）。原件定位：Vue 资料第 17–25 页。
- 学习目标：设计开启/关闭、焦点、键盘、遮罩点击、滚动锁定和层级管理。
- 暂定解释：可用组件不只是控制 `v-if`；还要规定打开前后的焦点去向与无障碍语义。
- 实验：实现一个可键盘关闭的弹窗，编写焦点返回和多弹窗叠层的用例。
- 待查证：Vue 的 Teleport、事件与组件 API，以及适用的 WAI-ARIA Dialog 交互建议。

### 04 Tree shaking 在 Vue 应用中的可观察结果

- 状态：**已核验并发布**（`vue-tree-shake-options`）。原件定位：Vue 资料第 11 页“更小/tree-shaking”及相关构建条件。
- 学习目标：区分“源码未调用”与“最终产物被移除”，理解打包条件。
- 暂定解释：树摇涉及 ESM 静态依赖、构建工具和副作用声明，不能仅凭框架名称保证所有未使用代码都消失。
- 实验：分别引入一个用到和一个未用到的 API，比较生产构建及 sourcemap 中的结果。
- 待查证：所用 Vue 与构建工具版本、生产模式、`sideEffects` 规则，以及原件是否把框架 API 和业务模块树摇混在一起。

## Java 路线：MySQL

### 05 范式与反范式的决策练习

- 状态：**已核验并发布**（`mysql-second-nf`）。原件定位：MySQL 资料第 1 页，主题 1。
- 学习目标：从依赖关系与更新异常解释规范化，再给出允许冗余的读取场景与一致性方案。
- 暂定解释：范式是建模工具，不是看到字段重复就机械拆表；读写比、事务边界和维护成本要一起考虑。
- 实验：设计订单与商品快照表，写出修改商品名称后历史订单应如何展示的规则。
- 待查证：资料对各范式的定义是否精确，案例是否混淆主键、候选键与函数依赖。

### 06 索引选择与执行计划

- 状态：**已核验并发布**（`mysql-index-kinds`）。原件定位：MySQL 资料第 1 页，主题 3–4。
- 学习目标：用查询谓词、排序、选择度和写入代价解释索引方案。
- 暂定解释：索引“存在”不等于优化器一定采用；先看真实查询与执行计划，再论证复合索引列顺序。
- 实验：同一张表对比无索引、单列索引与复合索引的 `EXPLAIN ANALYZE`，记录行数和执行时间。
- 待查证：不同索引类型与存储引擎的适用范围、版本，以及资料中的“最左前缀”表述是否过度简化。

### 07 事务隔离：现象、语句与引擎实现

- 状态：**已核验并发布**（`mysql-isolation-levels`）。原件定位：MySQL 资料第 3–4 页，主题 10。
- 学习目标：用两个会话重现脏读、不可重复读与幻读，明确隔离级别和读取方式。
- 暂定解释：教科书现象表不等于 InnoDB 所有语句的实际表现；普通一致性读和锁定读需分开讨论。
- 实验：建立两个事务，记录各隔离级别下两次查询的结果与锁等待。
- 待查证：MySQL 8.4 的默认隔离级别、快照读与当前读的官方描述；原件是否把标准定义当成 InnoDB 实测保证。

### 08 大字段拆表与覆盖索引

- 状态：**已核验并发布**（`mysql-wide-column-split`）。原件定位：MySQL 资料第 4 页，主题 11。
- 学习目标：根据热点列、行大小、IO 和关联查询成本判断是否拆出 `TEXT` 字段。
- 暂定解释：拆表可能缩短热点记录，也会增加 join 或额外查询；不能仅因字段大就断言一定更快。
- 实验：构造有大字段的读多写少表，分别测列表查询、详情查询和更新，同时查看执行计划。
- 待查证：InnoDB 行格式与页外存储行为、版本差异、资料中的性能结论是否具备测量前提。

### 09 Upsert 与并发唯一性

- 状态：**已核验并发布**（`mysql-upsert`）。原件定位：MySQL 资料第 6 页，主题 17。
- 学习目标：区分“先查再写”和唯一索引保障下的原子 upsert 路径。
- 暂定解释：并发正确性依赖唯一约束、冲突处理语句与事务语义，单纯应用层检查可能发生竞争。
- 实验：并发提交相同业务键，比较有无唯一约束时的最终行数与错误处理。
- 待查证：MySQL 8.4 `INSERT ... ON DUPLICATE KEY UPDATE` 当前语法及受影响行数语义；资料中的旧语法是否仍推荐。
