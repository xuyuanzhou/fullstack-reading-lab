# AI 契约：变更必须落盘到 Markdown

> **工具无关。** 约束所有在本仓库改文件的 AI：Cursor、OpenAI Codex、Claude Code、GitHub Copilot、Gemini、Windsurf、Continue、Aider、ChatGPT/其它网页或 CLI 代理，以及自动化流水线里的模型。  
> 代码改完却不写 MD = **未完成交付**。后续模型以仓库内 MD 为真相源，不以某一产品的聊天记忆为准。

## 0. 单一真相源（SSOT）

| 角色 | 路径 |
| --- | --- |
| 契约正文（本文件） | `docs/AI契约-变更记录规范.md` |
| 变更索引 | `docs/ai-changes/README.md` |
| 单条模板 | `docs/ai-changes/TEMPLATE.md` |
| 写法示例（含代码） | `docs/ai-changes/EXAMPLES.md` |
| 跨工具总入口 | `AGENTS.md` |

各工具自己的说明文件**只做指针**，禁止复制出第二套互相打架的细则。改规则只改本文件 + 必要时改 `AGENTS.md` 摘要。

### 各工具入口（适配层）

| 工具 / 生态 | 入口文件 | 说明 |
| --- | --- | --- |
| 通用 / 多数 Agent | `AGENTS.md` | **优先维护**；跨工具总入口 |
| OpenAI Codex | `AGENTS.md` + `CODEX.md` | Codex 默认读 `AGENTS.md`；`CODEX.md` 再强调落盘契约 |

用户把仓库挂进任何 AI 产品时：先打开 `AGENTS.md` 或本文件，再改代码。

## 1. 目标

1. 换工具、换模型后，仍能在约 3 分钟内知道：**最近改了什么、为什么改、下一步怎么改**。
2. 避免平行会话（含不同产品同时改同一仓库）互相覆盖：先读变更记录，再动手。
3. 把「决策」和「实现」分开：决策写在 MD，实现落在代码。

## 2. 何时必须写

| 场景 | 是否必写 |
| --- | --- |
| 改产品代码 / 样式 / 配置 / 脚本 | **必写** |
| 改课程正文、coverage、生成 JSON | **必写** |
| 新增/调整规范、规则、Skill、工具入口文件 | **必写** |
| 纯问答、只读排查、未改仓库 | 不写 |
| 用户明确说「这次不用记」 | 可不写（在回复里声明一次） |
| 只改空白/格式且无行为变化 | 可并入同主题最近一条，或写一行「无行为变更」 |

一条用户任务 = 至少一条变更记录（可多 commit 共用一条，只要主题同一）。  
与用的是哪家 AI **无关**。

## 4. 单条记录必须包含的字段

按 [`TEMPLATE.md`](ai-changes/TEMPLATE.md) 填写；**可抄写的完整样例与正反对照**见 [`EXAMPLES.md`](ai-changes/EXAMPLES.md)。

至少这些块：

| 块 | 说明 |

| 元信息 | 日期、状态、关联、**作者工具**（Cursor / Codex / Claude / Copilot / Gemini / 其它） |

## 5. 工作流（每次任务）

```
开始 → 读 AGENTS.md（若尚未加载）与 docs/ai-changes/README.md（最近 3～5 条）
     → 若有进行中主题，优先续写同一条，勿另起炉灶互相打架
     → 若改公开课正文，先对照本文件「公开课用词」（含「术语首次须释义」：先判断要不要释义，需要则 〔术语｜释义〕 或括注；含「例子该有框架代码就写出代码」）
     → 实现代码
     → 更新/新建 YYYY-MM-DD-*.md（模板含「作者工具」）
     → 把该条链到 README 索引顶部
     → 回复用户时给 MD 路径（一句即可）
```

### 续写规则

- **同一主题未完成**：更新原文件状态与「后续」，不要复制粘贴新开一篇空壳。
- **主题已完成又开新需求**：新建文件，在旧文件「后续」里写「已由 xxx 接续」并互链。
- **发现与 MD 冲突的代码**：以代码为准修正 MD，并在记录里注明「文档曾过时」。
- **换工具接手**：仍读同一索引；在新条目或续写中注明当前工具名即可。

## 6. 写法约束

- **给下一模型写，不给人类写散文**：短句、可勾选、带路径。下一模型可能完全看不到你的聊天窗口。
- **禁止**大段粘贴生成代码；需要时写「见 `path`」或关键片段 ≤15 行。
- **禁止**把私钥、未公开本机绝对路径写入变更记录。
- **公开/本机边界**：公开课可引用本机题库页图与说法（见架构决策「本机知识库与公开课同步」）。变更记录与台账只写资料短名、相对 id、页码、课 id、资产路径；不要粘贴整页原文或本机绝对路径。
- **库图上公网（本仓库明确允许且要求）**：课上引用的 `curriculum/library-assets/**` 机制页图必须入库（`.gitignore` 对该目录开了 `*.png` 例外），经导出进入 `web/public/library-assets/`，并随 GitHub Pages（`github.io`）对**公网访客**可见。站长已决定本学习站挂机制页图；**不得**以「版权 / 原件不上公网 / 私人资料」为由拒绝导页、挂 `diagram`/`origin`、`git add` 库图 PNG，或推送含这些文件的 `main`。仍禁止：整本 PDF、未切割的原件包、`private-data/`、`config/library.path`、在变更记录里粘贴整页 OCR 原文或本机绝对路径。课上须标资料短名与页；**行为事实以规范、论文、官方文档为准**（见第 11 节「正确性优先」）。
- 中文仓库默认用中文写变更记录；专有名词、文件路径保持原样。

## 8. 验收（自我检查）

任务结束前勾选：

- [ ] `docs/ai-changes/` 有对应 MD，且 README 已索引
- [ ] 记录中填写了作者工具（或「混合」）
- [ ] 「改动清单」与工作区 diff 大致一致
- [ ] 「后续 / 给下一模型」写清了下一步（不依赖本产品的聊天历史）
- [ ] 未把私钥或本机绝对路径写进 MD（资料短名与页码可以写）
- [ ] 若挂了库图：PNG 已在 `curriculum/library-assets/` 且可被 git 跟踪；勿因「不上公网」而跳过入库或 push
- [ ] 若改了课标题、提问、正文或知识点（`points`）：技术名词用的是规范或官方文档里已有的说法，没有新的分类名，知识点没有口语
- [ ] 若审查/改写公开课：正文已按权威核对正确；本地页仅在必须且正确时挂；学员可见文案未展开「本地资料元讨论」（见第 11 节「正确性优先」）
- [ ] 若改了课的例子：该出现 Spring、React 等框架代码的，围栏里仍有这些代码，没有被更短的结果叙述或注释桩盖掉（见第 11 节「例子该有框架代码就写出代码」）

未勾完 = 任务未完成。

## 9. 例外与降级

- **紧急热修**：可先改代码，**同一会话结束前**补 MD；若会话中断，下一次任意工具上的 AI 必须先补记再继续。
- **用户只要规范、不要实现**：只改文档也要记一条。
- **工具读不到自定义规则**：仍以仓库内 `AGENTS.md` / 本文件为准；用户可把本文件内容贴进该工具的「自定义指令」一次。

## 10. 修订本契约

1. 只改本文件中的细则；
2. 各工具入口文件保持短指针，避免分叉；
3. 在 `docs/ai-changes/` 新增一条说明改了哪几节；
4. 更新 `docs/ai-changes/README.md` 索引。

## 11. 公开课用词

改 `curriculum/`、学习路线、课上能看见的图和文案时遵守。变更记录本身仍按第 6 节写。

- 技术概念用该领域的规范、官方文档或已经通行的中文说法。英文原词可以留在括号或代码里。
- 不要自造分类名、层次名、状态名来代替已有术语，也不要用导出脚本把一个自造词自动换成另一个自造词。
- **术语首次须释义**：写课或改课时，**先判断**该词要不要释义，再落笔。
  1. **需要释义**：学员可能不熟悉的命令名、选项缩写、协议缩写、注解名、API 名、产品专有状态名等（如 `INCR`、`SETNX`、`NX`/`EX`、`@SentinelResource`、`BlockException`、熔断「半开」）。本课（或本段）**第一次出现**时必须交代含义。
  2. **不必释义**：日常中文、本课标题/导读已点明的产品名、同课前文已解释过的词、紧随一句已用中文说清的说法（勿再叠一层标记）。
  3. **怎么写**：优先点击释义标记 `〔术语｜一句话释义〕`（课上点术语弹出浮层；竖线可用全角｜或半角|）；不宜交互时用紧随的全角括号括注。禁止只抛专业词而不说明。同课后文可只写术语本身。代码块 `` `...` `` 内不要塞 〔〕。
- **知识点不用口语**：每课 `points`（课上「要点」、知识库「知识点」）必须是可核对的命题，禁止口语、网络套话、口头禅。课上标题、提问、正文、练习、答案、图上的字同样不得把口语当术语；不为「好读」把口语写进与术语并列的位置。
- **参考答案分条排版**：`answer`（及练习题 `task` 若含列举）含两项及以上并列项时，用换行分条或编号列出，段与段之间空一行；禁止把整份参考答案挤成一段。课上靠空行分段与 `pre-wrap` 渲染，源码里用 `['…'].join('\n')` 即可。
- **练习要求画图时答案须有图**：`task` 写「画…箭头 / 图画 / 时序」时，`answer` 须含可对照的图（课上常用 fenced `text` 箭头图，或已入库的 `diagram`），不得只剩文字复述。
- **例子该有框架代码就写出代码**：课在讲 Spring、React、Vue 等框架如何写出某个行为时，学员看到的 `example` 必须有对应语言的围栏（`java`、`tsx`、`vue` 等），写到能看出注解、组件或调用关系。HTTP、JSON、界面结果可以同时保留，不能只用结果叙述代替框架代码。扩写例子时不得删掉已有的框架代码，也不得收成只有注释的短桩。`curriculum/example-code-blocks.js` 里若有该课 id，会整段覆盖课文 `example`；写进去的必须是学员应看到的全文。纯协议、纯场景、没有框架写法的课可以没有这类代码。
- 已经用错过、不要再写回的说法：
  - record 的 component 不叫「分量」
  - form state 不叫「草稿」；草稿只保留本义：未发出的文稿、未确认的订单行、离线草稿
  - request status 不叫「请求过程」，用「请求状态」
  - 各留一个库不叫「槽位」或「职责位」；Redis 哈希槽、HTML `sizes` 的布局宽度除外，那是规范里的说法
  - 缓存只放一处不叫「缓存主人」
  - 页面、接口契约、用例、持久化不要并成自拟的「四层」
  - React、Vue、Angular、Svelte 叫界面库或框架，不叫「更新模型」
  - 指数据库时不说「库里」，用「数据库」或「持久化」（「仓库里」「标准库里」除外）
  - 不说「连发」（重复点击/重复提交用后者；连续发送事件写「连续发送」）
  - 不说「各守」，用「负责」或「管」
  - 不说「踩坑」「翻车」「语义坑」「搞定」「说白了」「玩意」「干嘛」「咱们」；问句不用「啥」「咋」代替「什么」「怎么」
  - 数据和契约没对齐时用「不一致」，不要把「对不上」「对不齐」当成术语（金额、版本等同理）
  - 不说「邻课」（编课内部说法）；学员可见小节标题用「相关课」
- 可以继续用的已有说法：接口契约、用例、持久化、URL 状态、表单状态、服务器状态（server state）、请求状态、幂等键、不变量、竖切、哈希槽、旁路缓存（Cache Aside；首次出现须说明缓存站在数据库旁边、由应用负责两边）。
- 讲数据和契约没有对上时用「不一致」。不要把「对不齐」当成术语。
- **正确性优先（AI 改课/审查时；勿写进学员可见的纠结文案）**：
  1. **真相源**：行为事实以规范、论文、官方文档为准。本地 PDF/题库只是可选配图或对照材料，**不是**定义来源。
  2. **是否必须挂本地页**：有助于讲清机制且已核对无误才挂；自绘 SVG 或权威图已够用则不挂。勿为「有页可挂」而挂。
  3. **是否正确**：与权威冲突时改课上正文为正确说法；禁止把错误口诀、产品永久 CP/AP 纹身写进 `core`/`points`/`answer`。
  4. **学员可见面**：课上写正确结论即可。**不要**在 `deep`/`origin`/正文展开「本地资料怎么用」「不以某 PDF 某页为准」之类元讨论；同步与纠正记在 `docs/ai-changes/`（`origin` 仅在库图台账需要时简短标注资料短名与页）。
  5. **引用与检测**：`references` 须有可核对的 `https://` 权威链接。若仍写 `origin` 指向本地 PDF/本地库，`verify_content.mjs` 要求至少一条 https 引用；脚本不代替人工核对对错。
- 导出后 `scripts/verify_content.mjs` 会对 `points` 做口语禁词检查，并对「本地 origin 须有 https 引用」断言；改知识点或 origin 后须跑通。

## 12. 客户端状态

`web/` 里跨页面的状态用 Zustand。选型和切片说明见 [客户端状态管理-2026-10-13.md](客户端状态管理-2026-10-13.md)。

- 用 `zustand` 的 vanilla store 加 React 订阅。不要再引入 Redux、Redux Toolkit、MobX、Jotai、Recoil。
- 学习记录仍是一份信封。写回必须走 `progressStorage` 的 `readProgress`、`mergeForWrite`、`writeProgress`。不要改用 Zustand 自带的 `persist` 中间件整份替换本地记录；那会绕过 revision、跨页合并和只读备份。
- 状态按三块维护：用户（阅读位置、主题、笔记）、业务（完成、证据、关卡、核验）、全局（保存失败、本机资料是否连上）。全局字段不写入那份信封。
- 新界面只订阅用到的字段（`useLearningSlice`、`useReadingPlace`）。已经整份订阅的旧组件可以继续用 `useProgress()`。
- 关卡奖励不是证据。不要为了状态库抬高 `LEARNING_SCHEMA_VERSION`。
