# 打包与首屏优化

日期：2026-10-07  
范围：`web/` 公开站（Vite 8 + React 19 + Ant Design 6）

## 现状结论

### 优化前基线

| 产物 | 约大小 | 说明 |
| --- | --- | --- |
| `index-*.js` | ~2.3 MB（gzip ~790 KB） | 主壳：antd + React Router + **整份 curriculum** |

### 第一刀后（index + 单体 bodies）

| 产物 | 约大小 | 说明 |
| --- | --- | --- |
| `index-*.js` | ~1.07 MB（gzip ~390 KB） | 主壳 + curriculum-index（含 core） |
| `curriculum-bodies-*.js` | ~1.22 MB | 课内正文；打开课页才下载 |

### 第二刀后（2026-10-07 续，实测）

| 产物 | 约大小 | 说明 |
| --- | --- | --- |
| `index-*.js` | **~625 KB**（gzip ~215 KB） | 主壳 + 无 core 的 index |
| `curriculum-bodies-frontend-*.js` | ~569 KB（gzip ~204 KB） | 切到/打开前端课才拉 |
| `curriculum-bodies-java-*.js` | ~1.10 MB（gzip ~388 KB） | 切到/打开 Java 课才拉 |

相对最初主包 **2.31 MB → 0.62 MB（约 −73%）**。首开某轨只下载该轨 bodies，不再一次拉 694 课全文。

## 已做（有效）

1. **AI 路由懒加载**：`AiPage` / `AiLabPage` / `AiProgressAside`；catalog 仅在 `/ai` 动态加载。
2. **切断 catalog → 题库硬依赖**；知识库分路搜课/搜题。
3. **勿用粗暴 `codeSplitting.groups`**：曾把 antd 误塞进 AI chunk 并被 preload。
4. **curriculum 两层拆分**：`curriculum-index.json` 同步；正文按轨 `curriculum-bodies-frontend.json` / `curriculum-bodies-java.json` 懒加载。
5. **`core` 移入 bodies**：知识库列表搜索用 title/prompt/keywords/points；课页仍有完整 core。
6. **切轨预取**：`AppLayout` 在当前轨与切换按钮上 `prefetchTrackBodies`。
7. **字体**：Google Fonts 使用 `display=optional`，减少首屏字体竞争。

## 文件职责

| 文件 | 内容 | 加载时机 |
| --- | --- | --- |
| `curriculum-index.json` | id/title/prompt/points/keywords + outline | 同步进主壳 |
| `curriculum-bodies-frontend.json` | 前端课 core + 正文 | 前端轨 / 打开前端课 |
| `curriculum-bodies-java.json` | Java 课 core + 正文 | Java 轨 / 打开 Java 课 |
| `curriculum.json` | 完整导出 | 仅校验/审计，运行时不进主包 |

导出：`scripts/export-curriculum.mjs`（`predev` / `prebuild`）。

## 测量方法

```bash
cd web && npm run build
ls -lah dist/assets | sort -k5 -h
# 看 index.html modulepreload：不应预载 AI / bodies-*
```

## 不要做的

- 不要把 antd / React 用自定义 group 绑到 AI chunk。
- 不要把 bodies 再同步 import 回 `AppLayout` / `routes`。
- 知识库若需按 core 深搜，应另做异步 search haystack，勿把 core 塞回主壳 index。

## 是否有必要继续？（评估 2026-10-07）

| 候选 | 预估收益 | 成本/风险 | 结论 |
| --- | --- | --- | --- |
| **去掉课表页整轨预取** | 冷开课表不再下 ~0.5–1.1 MB bodies | 低：悬停/聚焦课链再预取 | **必要（已做）** |
| 换掉 antd 侧栏/Menu | 主包 gzip 或再降数十～百余 KB | 高：重写壳层、视觉与无障碍回归 | **暂不值得** |
| 按章再拆 bodies | 单课首包更小 | 中：导出/缓存复杂度↑，收益递减 | **暂不值得** |
| 自托管字体子集 | 少一次 Google RTT | 低～中：构建链路 | 可选，非瓶颈 |
| 部署 hash 长期缓存 | 回访几乎不重下 | 低：CI/Pages 头 | 部署时做即可 |

**判断**：数据层拆分已吃掉最大块（主包 2.3 MB → ~0.62 MB）。剩余主壳 gzip ~215 KB + React ~100 KB，对学习站可接受。继续砍 antd 属于产品级重构，不是打包缺口。

曾有问题：`AppLayout` 一进前端/Java 轨就 `prefetchTrackBodies`，课表页也会拉整轨正文，懒加载形同虚设。现改为 **仅悬停/聚焦课链预取**，真正打开课仍由 `loadFullLesson` 拉取。

## 下一刀（可选，非必须）

1. 部署侧对 `*.js` hash 资源设长期 `Cache-Control`。
2. 自托管字体子集（去掉 Google 外链）。
3. 若将来要换设计系统，再评估去 antd。

## 验收口令

- `cd web && npm test && npm run build`
- 冷开站点（非课页）→ 不应先下 `aiCatalog` / `aiInterviewBank` / `curriculum-bodies-*`
- 打开前端课 → 只出现 `bodies-frontend`；打开 Java 课 → 只出现 `bodies-java`
- 课页正文完整（含 core / deep / references / diagram）
