# 客户端状态管理

日期：2026-10-13。对象是 `web/` 这个 Vite 8、React 19 的学习站。

## 选型

选用 Zustand 5.0.15。不引入 Redux Toolkit。

本站没有多人会话，也没有服务器上的账号。跨页面要记住的是一份学习记录：阅读位置、笔记、完成勾选、证据和关卡。写回浏览器之前必须和另一页已经落盘的记录合并，记录比本页新时只能读。这套合并在 `web/src/state/progressStorage.ts`，不该再包进另一套 reducer。

| | Zustand 5.0.15 | Redux Toolkit 2.13.0 + react-redux 9.3.0 |
| --- | --- | --- |
| 最近发布 | 2026-08-13。React 18 及以上 | 2026-09-29。React 16–19 |
| 本次打包 | `createStore` + `useStore` + `useShallow`，gzip 725 字节 | `configureStore` + `createSlice` + `useSelector`，gzip 9.9 KB |
| 和现有代码 | 动作就是函数，测试不必渲染 React | 要拆 reducer、action、dispatch，合并逻辑得再搬一次 |
| 订阅 | 组件可以只订一个字段 | 也可以，但要多一层 selector 和 Provider |
| 持久化 | 自带 `persist` 会整份替换本地记录 | 同样要自己接 `mergeForWrite` |

体积用 esbuild 0.25.10 压缩后 gzip，`react` 和 `react-dom` 算外部依赖。Redux 那次还带上了切片示例里的 Immer。

Zustand 的 `persist` 中间件不用。学习记录的写回仍是 `readProgress` → `mergeForWrite` → `writeProgress`。

## 架构

一个仓库，三块动作，一份快照。

```text
用户切片          业务切片              全局切片
位置、主题、笔记   完成、证据、关卡、核验   保存失败、本机资料是否连上
        \              |                /
                 LearningState
                      |
            revisionPersist（合并后再写）
                      |
                 progressStorage
```

| 切片 | 文件 | 放什么 | 不放什么 |
| --- | --- | --- | --- |
| 用户 | `web/src/state/slices/userSlice.ts` | 轨、组、最近阅读、笔记、主题、站内搜索、本机资料筛选 | 完成勾选、证据 |
| 业务 | `web/src/state/slices/businessSlice.ts` | 完成、复习、路径自评、AI 路线、核验、草稿、暂停、关卡 | 主题、本机是否连上 |
| 全局 | `web/src/state/slices/globalSlice.ts` | `storageIssue`、`localReady`、对本机资料服务的探测 | 任何要进信封的字段 |

`revision` 不属于某一块。只有合并写回时才增加。探测本机资料不会改 `revision`，也不会写本地记录。

记录比本页新时，业务切片的草稿、暂停和关卡动作直接返回，不改信封。关卡动作仍调用原来的 `applyQuestAction`，不把奖励写成证据。

壳层接线在 `web/src/state/progress.tsx`：主题写到 `documentElement.dataset.theme`，离开页和另一页的 `storage` 事件走 `web/src/state/revisionPersist.ts`。变更后 350 毫秒合并写回；`pagehide` 立刻写。

## 使用

整份记录，旧组件继续这样拿：

```tsx
const progress = useProgress()
progress.setNote(id, note)
```

只跟主题有关的壳，不要订整份记录：

```tsx
const themeName = useLearningSlice((state) => state.theme)
```

只跟当前轨、组有关：

```tsx
const place = useReadingPlace()
```

本机资料是否连上是全局切片。后发起的探测覆盖先返回的结果；探测抛错当成没连上。

```tsx
const localReady = useLearningSlice((state) => state.localReady)
const reconnectLocal = useLearningSlice((state) => state.reconnectLocal)
```

测试造一个不自动写盘的仓库，需要落盘时调用 `flushPersist()`。见 `scripts/learning-store.test.mjs`。

## 性能

- 主题只订 `theme`。改笔记不会让包住全部路由的 `ThemedApp` 重绘。
- 继续阅读只订轨和组。
- 动作函数放在仓库里，引用不变。`useShallow` 不会因为函数换了新对象而重绘。
- 不引入 Immer。更新沿用原来的浅拷贝。
- 全局字段不在 `progressSnapshot` 里，所以探测和保存失败的提示不会触发写盘。
- 学习记录的 debounce 仍是 350 毫秒。不要为了「更快」改成每次按键都 `setItem`。

## 不要做的事

- 不要把 `motion` 或图标库的状态放进这个仓库。
- 不要用第二份本地键保存同一份学习记录。
- 不要为了切片把 `LEARNING_SCHEMA_VERSION` 从 2 抬高。
