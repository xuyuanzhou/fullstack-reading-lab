# 公开站点与本机资料的架构决策

2026-10-06 起，公开学习站改为 **React + TypeScript + Vite + Ant Design**，源码在 `web/`。本机私有题库仍由 **Python** 阅读器提供 API。两者边界不能混。

## 先分清两个入口

公开学习站 `https://xuyuanzhou.github.io/fullstack-reading-lab/` 由 GitHub Actions 构建 `web/` 并部署 `web/dist`。访客只需打开网址。

`启动阅读器.command` / `reader/server.py` 只用于购买者在**自己的电脑**查看私人 PDF、图片、密码保护文件和全文索引。浏览器网页不能直接枚举另一个人的本机文件；无论公开界面用原生 JavaScript 还是 React，要读取这些本机资料都需要用户主动选择文件，或保留一个仅监听本机的服务。资料库目录来自 `--library`、环境变量 `READING_LAB_LIBRARY` 或 `config/library.path`，仓库里不写某台机器的路径。

## Python 保留什么、去掉什么

**保留（本机工具链）：**

- `reader/server.py`：本机 HTTP + `/api/*` + 科目目录 + OCR/PDF
- `reader/import_library.py`、`import_archives.py`、`import_embedded.py`、`parsers.py`
- `reader/mark_sources.py`、`review_empty_images.py`、`source_progress.py`
- `reader/tests.py`：校验本机阅读器与科目分类
- `private-data/`：仍被 Git 忽略，留在仓库根目录

**不再承担公开站点职责：**

- `legacy/` 里的 `index.html` + `app.js` 不再是部署产物
- `scripts/build_public.py` 调用 `web` 的 npm build，并把结果镜像到 `./dist` 以便兼容

**课程正文的权威来源：**

- `curriculum/` 里的 `lessons.js` / `coverage-*.js`
- `scripts/export-curriculum.mjs` 导出 `curriculum.json`（完整校验用）以及运行时用的 `curriculum-index.json` + `curriculum-bodies.json`，并把 `curriculum/diagrams` 与 `curriculum/library-assets` 复制到 `web/public/`
- React 主壳同步读 index；课页再懒加载 bodies。详见 `docs/打包与首屏优化-2026-10-07.md`

## 本机知识库与公开课同步（2026-10-10 起）

公开课可以、也应当吸收本机题库的标准说法与机制图：

- 页图 / 库内 PNG 经 `reader/export_page_asset.py` 导出到 `curriculum/library-assets/<slug>/pXXXX.png`，随导出进站。
- **`curriculum/library-assets/` 必须入库**（`.gitignore` 对 `*.png` 开了该目录例外）。GitHub Actions 无本机题库，不入库则 `github.io` 上库图 404。
- **上公网是本站策略**：课上引用的机制页图随 Pages 对公网访客可见；不把整本 PDF 或未切割原件包放进仓库。AI 契约第 6 节写明不得以版权为由拒绝入库与部署。
- 导出只把课上引用的库图（及 `/ai` 手册图）复制到 `web/public/library-assets/`，再打进 `web/dist`。
- 课上用 `origin` 标资料短名与页码；有库图时课页写「来源」，自绘 SVG 仍可写「教学重绘」。
- 正文写成标准知识点（定义 → 机制 → 资料常见写法 → 例子 → 自检），不整本粘贴 PDF。
- 行为事实仍对照官方文档或固定版本源码；过时说法写清「旧资料 → 现行结论」。
- 变更记录与台账只写相对资料名与页码，**不写本机绝对路径**；`config/library.path` 仍不提交。

完整阅读与 OCR 仍只在本机 `reader/`；公开站不依赖访客本机文件，但**会**托管已导出的课上库图。

## 仓库结构

```
web/                 React 公开课（Ant Design UI）
curriculum/          课程正文、原创 SVG、library-assets 页图
reader/              本机私有题库工具（Python）
scripts/             导出、校验、公开构建
docs/                选题、核对、library-sync 台账与架构记录
legacy/              旧的零构建页面
config/              本机资料库路径（library.path 不提交）
```

## 本地开发

```bash
# 终端 1：本机题库 API（可选；路径来自 config/library.path）
python3 reader/server.py --no-browser

# 终端 2：React 开发服务器（/api 代理到 4180）
cd web && npm run dev
```

只预览公开课、不看私人资料时，只需 `cd web && npm run build && npm run preview`。

先构建再开阅读器时，`reader/server.py` 提供 `web/dist`，同一地址同时有公开课 UI 与 `/api`。

## 为何公开站改用 React

公开课需要稳定的路由、侧栏阶段、知识库筛选、本机资料联调入口和可维护的组件边界。零构建脚本能承载早期课量，但目录与主线继续扩张后，信息架构和工程维护成本更高。React Mastery Lab / Vue 3 Mastery Lab 仍只做源码实验，不把本站改造成第二套源码阅读器。
