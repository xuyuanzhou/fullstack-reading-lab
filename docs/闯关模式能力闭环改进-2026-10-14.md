## 一、背景与现状（对照代码）

当前结构（见 `docs/ai-changes/2026-10-14-path-atlas.md`）：

### 原诊断仍成立

1. 「阅读 · 交付」二分无法回答「会不会」
2. 路径对所有人同一套，无显式难度档
3. 子任务完成后反馈偏弱
4. 主线/支线/Boss 关系靠文案，缺可跳过的验证入口

仓库里**已有半成品**，不要推倒重做：

| 已有 | 位置 | 用途 |

## 二、对「上一版过设计」的同意项

同意：不做动态难度引擎、叙事身份、三层奖励、推倒式技能树。  
同意：P0 = 能力闭环；P1 = 依赖与跳过；P2 = 反馈；P3 = 基础/进阶验证。

---

## 三、设计原则（落地口径）

1. **能力导向**：关卡完成标准要能指向「验证通过」，但界面必须标清证据来源（本地检查 / 待复核 / 旧版自评），**不得写成平台认证**。
2. **增量改造**：保留主线/支线/Boss 石台总图与现有 query。
3. **认知负荷优先**：一关一个能力句；验证入口一个主按钮。
4. **可验证可度量**：优先复用已有任务 id 与证据，不新建第二套进度库。

## 四、核心方案（对齐后的改写）

### 4.1 关卡：任务清单 → 能力闭环

| 阶段 | 完成标准 | 现有对应 | 改造 |
| --- | --- | --- | --- |
| 输入 | 必读槽已读 | `done` / 阅读条 | 保留 |
| 输出 | 交付勾选 | `pathChecks` / 交付条 | 保留 |
| 验证 | 该关验证任务达到声明的证据标准 | `LEARNING_TASKS`、笔试、本地 lab | **新增展示与门闩（分阶段）** |

验证形式（按关选用，不三种齐上）：

- **概念**：站内可判分的小题（已有笔试骨架）→ 可标「本地检查通过」
- **场景**：写思路 + 参考答案自评 → 只标「自评完成，待复核」
- **代码**：本机样板 + 预设用例（如 `labs/order-g1g2`）→ 学员登记结果先待复核；将来才接可信运行

**通关门闩分两步上线**（避免一次切断旧用户）：

1. **P0a**：界面出现「验证」第三段进度；能力目标用现有 `pass` 升格展示。旧 `gateCleared` **暂不改**，旁注「旧版已过 / 新版待验证」。
2. **P0b**：新用户或显式切换后，该关「新版已通过」才要求验证证据达标；旧勾选永不抹掉。

### 4.2 关卡关系：依赖标记 + 跳过验证

总图保持现在的主线、支线和 Boss 石台，不另画技能树，不画前置箭头，不增加节点。依赖只出现在关卡页的一句话里。

**数据。** 每关增加 `requires: string[]`，只列直接前置，全部都要满足。没有 `anyOf`。支线不进这张表，仍用现有「建议穿插」文案。Boss 不设前置。

| 关卡 | requires | 建议先完成的原因 |
| --- | --- | --- |
| g1 走通一次下单 | 无 | 起点 |
| g2 把写入做对 | g1 | 先有一条写路径，再谈不变量 |
| g3 把读取做对 | g2 | 读的是已经提交的结果 |
| g-auth 谁能改这一行 | g1 | 先有可改的那一行 |
| g-test 用测试锁住 | g1 | 先有一种可观察的行为 |
| g-triage 一次故障先定位再改 | g2、g3 | 定位要同时看写入和读取留下了什么 |
| g4 决定拆不拆 | g2 | 拆分之前先守住一次写入 |
| g5 上线后能看见故障 | g-triage | 先会定位一次故障，再谈线上信号 |
| g6 到工作里推动 | g4、g5 | 材料来自拆分决定和上线后的可见性 |

一关最多三条直接前置。界面只写这些关的 `learnTitle`，不展开它们各自的前置。

**什么叫「建议先完成」。** 前置关 `gateCleared` 为真，或该关已是「新版已通过」，才算这条建议已满足。只用旧勾选也算满足建议，避免把旧用户挡在验收外面。不满足时，关卡页在口径说明下多一行：「建议先完成「把写入做对」」。两、三条用顿号连起来，并各给一个进该关的链接。

**什么都不锁。**

- 课文链接始终可点。
- 总图石台不改成灰色，不出现「未解锁」。
- 阅读路、交付路照旧可进。
- `gateCleared`、下一关推荐、`openIndex` 都不读 `requires`。
- 没有验证题的关（例如 g-auth）只显示建议句，不铺空石台，也没有跳过按钮。

**验收入口三种字。** 只改验证石台上的短状态，石台仍可点。

| 条件 | 石台短状态 | 说明 |
| --- | --- | --- |
| 前置都已满足 | 可挑战 | 没有额外说明 |
| 前置未齐，且学员还没选择跳过 | 建议先完成 | 上面那句建议；点石台仍进入这一道 |
| 学员已选择跳过 | 可挑战 | 「已跳过建议先修。通过只记这一关。」 |

跳过是关卡页上的一个文字按钮：「跳过建议，直接验证」。只在「有验证题、前置未齐、尚未跳过」时出现。点下去把该关 id 写入学习记录的 `skipVerify` 列表。这只记住选择，不改勾选、不改证据、不把前置关标成已过。

跳过之后做出的通过，只记**这一关**自己的验证证据。前置关保持原来的「旧版已过 / 进行中 / 新版待验收」。没有本地检查通过或已登记的人工评审时，跳过不能变成「新版已通过」，也不能叫免修认证。

### 4.3 反馈：信息量优先，奖励克制

不做三层奖励。不加经验值、连击、掉落、段位、称号，也不在总图上再铺一套徽章。任务板上已有的「记下」标记保持原样：本机标记，不改变九关勾选，不升成奖励柜。

反馈只有三下，每一下都说明**记下了什么、还缺什么、这不证明什么**。没有弹窗。动效沿用已有的轻轻一闪，并尊重系统的减少动效设置。音效仍默认关闭。

| 时机 | 出现在哪 | 文案必须包含 | 不出现 |
| --- | --- | --- | --- |
| 记下一项交付，或保存一道验证草稿 | 该石台旁一行，约 2 秒 | 短名 + 「这是自评，待复核」 | 分数、徽章、「过关」 |
| 一项达到本地检查通过 | 该石台状态改成「本地检查通过」，旁注还剩几项 | 题版本或检查范围 + 「这不是认证」 | 把整关标成新版已通过 |
| 这一关每一项都是本地检查通过或已登记评审 | 关卡页顶一条，不超过 2 秒，用该关 `pass` | 「新版已通过」+ 能力句 + 「这一关不是精通」 | 庆祝页、经验、称号 |

同一条记录刷新、重复导入，不重复播。失败或未通过只说还缺哪一项、已经保留了什么，不写「失败」或「退回上一关」。

阶段雷达仍属后一步：维度先手填，不从阅读数或勾选推算等级，也不当作奖励。成就表里的固定事实以后可以做，这一步不建成就柜。

### 4.4 难度

当场问答和每关第一道选择题是基础，计入验证条和「新版已通过」。其余选择题是进阶：石台上写「进阶」，记下后标「进阶记下」。进阶不进分母，不挡下一关，也不是认证。不做全自动动态难度。

## 七、结论

方向正确：从进度消费转向能力验证。落地时必须接上现有证据模型，并分 P0a/P0b 迁过关口径，否则要么假认证，要么一次改坏旧进度。

P0 到 P3 已落地。阶段雷达和成就柜仍不做。不要补经验或徽章。闯关页仍不画技能树；技能树若做，是另一页，见 `docs/技能树加页设计-2026-10-15.md`。
