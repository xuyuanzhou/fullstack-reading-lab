## 1. 原先的问题

| 问题 | 表现 |
| --- | --- |
| 基础未前置 | 「Java 基础」排在 Spring 之后；HTML/CSS 排在 React 之后；TCP/HTTP 混在前端列末尾 |
| 赛道交叉 | 「后端」里同时有 Java 语言、Spring、Nacos/Dubbo/Seata、网关；「数据与中间件」把库、缓存、MQ、搜索揉在一列 |
| 领域边界糊 | TCP/HTTPS/WebSocket 标成前端；算法标成后端；限流熔断与 Sentinel 分属两列却缺少清晰的「中间件 vs 分布式」分界 |
| 无子层级 | 只有六列，组内没有「入门 → 框架 → 跨端」等子分类，阅读顺序靠追加时间 |

## 2. 排序逻辑依据

1. **赛道从左到右**：计算机通用基础 → 领域入门（前端 / Java / 数据）→ 中间件 → 分布式与高并发 → 工程与运维 → AI → 架构。符合「先通识，再栈，再设施，再方法论」。AI 放在架构前，因为架构列要留在最右。
2. **组内从上到下**：同赛道内按子分类递进；同一子分类内按依赖从浅到深（例如 Web 入门：HTML → CSS → JS → 浏览器 → TS）。
3. **前置 `allOf`（最多两个）**：只表示缺了它就读不懂。例如 HTTP 要 TCP；JS 要 HTML；Spring 要 Java；MySQL 要 SQL；Kafka 要消息队列总览；K8s 要 Docker；Sentinel 要限流熔断。Redis、消息队列、分布式一致不再绑在 MySQL 上。全栈叙事里的「通常接着学」不打暗印章。
4. **不做什么**：不改九关与 `gateCleared`；已点亮不是岗位认证；不为没有课文的词条造空节点。

| Redis / ES / MQ 产品 | 数据与中间件 | 中间件（库不进此列） | 数据存储只留库与建模 |
| SQL / 表结构 / MySQL | 数据与中间件且 SQL 靠后 | 数据存储 · 先 SQL 再库 | 建模与引擎递进 |
| 幂等 / Saga / 锁 / Outbox | 高并发 | 分布式与高并发 · 一致性 | 模式与产品课分离 |
| 限流熔断 | 高并发 | 分布式 · 容量；Sentinel 紧随其后 | 概念与产品同一组 |
