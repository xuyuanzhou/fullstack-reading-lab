## 1. 直接回答

**全栈学习路线要不要推倒重来？**

**内容不用推倒；组织方式要改。**  
侧栏章节、719 课可以大体保持原样当「工具书」。  
**改的是：默认学什么、怎样算学完、和架构师主线怎么接。**

若保持「从前到后刷完前端轨 / Java 轨」的暗示不变，用户会继续以为学完 = 高级 / 架构师——这才是乱的根源。

## 2. 三条路线，各管一件事

| 路线 | 目标头衔 | 学完标准 | 和课库关系 |
| --- | --- | --- | --- |
| **A · 全栈交付线** | 能独立做通一条业务的高级全栈开发 | 交付物 F1～F3（见下） | 主线 8 课 + 按缺口抽章 |
| **B · 架构师线** | 高级架构师候选人材料 | D1～D6（见架构师主线设计） | ≈ A 的加深 + 拆分/分布/运行 + **课外 D6** |
| **C · 索引线** | 查漏补缺 | 无「学完」 | 其余全部章节，用到再查 |

关系：

```text
索引线（默认折叠的章节库）
        ↑ 查
全栈交付线 ──加强──→ 架构师线（多关卡 4～6）
```

- 只做 **A**：成为「能交付的全栈」，够用。  
- 做完 **A 再走 B**：冲架构师。  
- **不要** 先把 C 线性刷完再谈 A/B。

## 3. 全栈路线具体怎么调（保持原样的 / 必须改的）

### 保持原样

| 保持 | 原因 |
| --- | --- |
| 前端 / Java 分轨 | 岗位入口不同，合理 |
| 各章知识点与课文 | 作为索引价值高，重写成本大 |
| 「全栈主线」4+4 课内容 | 已是正确脊柱，继续当 **唯一强制序** |
| React / Vue Mastery 外链 | 原理加深用，不并进主进度 |

### 必须改（组织与文案）

| 改什么 | 现在 | 调整为 |
| --- | --- | --- |
| 默认顺序 | 暗示：主线 → 语言 → … → 工程整章刷完 | **强制只序贯：全栈主线 → 按缺口点名抽课**；其它章默认「按需」 |
| 学完定义 | 易被理解成课数 / 进度条 % | **F1～F3 交付物**；% 只表示「索引覆盖」，不叫「全栈毕业」 |
| 双轨关系 | 两轨各刷一遍 | **同一条业务竖切同时碰两侧**（页面契约 + 服务数据），不是先读完前端再读 Java |
| 与架构师 | 无边界 | 首页写清：全栈线 = A；架构师 = B；B 含课外关卡 |
| 大章位置 | 微前端、全量 SCA、RN/Flutter 与主线同级压迫感 | 标成 **选修 / 索引**；未过 F1 不推荐进 |

### 全栈交付线的「学完」：只有三个交付物

与架构师 D1～D3 对齐，但**止步于能交付**，不强求拆服务 ADR。

| 交付物 | 含义 | 对应架构师 |
| --- | --- | --- |
| **F1** | 页面、接口契约、用例、持久化各守什么 + 一条写路径能演示（含失败 type，**不要求**并发压测套件） | 对齐 D1；弱于 D2 |
| **F2** | 读路径 +（缓存失效 **或** N+1）有证据 | 对齐 D3 的一半；架构师关卡 3 要求两者都有 |
| **F3** | 幂等重试不双写，或一种简化异步（**不要求**完整 Outbox） | 弱于 D2/D4；冲架构师时升级为 D2 + D4 |

**全栈线毕业 = F1+F2+F3，不是 256+463 课读完。**

### 推荐的全栈默认路径（短）

```text
1. 前端全栈主线 4 课 + Java 全栈主线 4 课（同一业务）
2. 只补缺口：事务、幂等、会话、N+1 或缓存（总共再加 ≤10 课）
3. 交 F1～F3
4. 其余章节 → 索引线；工作遇到再查
5. 若目标改为架构师：F1～F3 已等价于 D1～D3 才从关卡 4 进入；否则先补关卡 2～3 的缺口，再进关卡 4～6
```

算法、设计模式、JVM 全文、微前端全文、SCA 全文：**不进全栈默认路径**。

## 4. 产品上建议怎么改侧栏（不必立刻改课文）

1. **侧栏只做章节目录**（前端 / Java / AI）  
2. **学习只走 `/paths`**：当前一关先写怎么读，再列课。只有下一节展开问题和三个要点，其余只留这一节要做的事。标了二选一的相邻两课算一节，读完其中一课就到后面。课表后面才是可勾选的交付。课读完并且条目都勾上，才打开下一关。后面几关只列交付物。第 3 关是全栈交付，第 6 关是架构师材料。不要把两条线再做成并列菜单  
3. **进度文案**：主线上的百分比把已读和交付合在一起，交付没勾完不到 100%。最后一节没记已读时，页顶不送去交交付物。  
   - 全栈：`交付 F1/F2/F3`  
   - 架构师：`关卡 1～6`  
   - 索引：`已读 x 课（查阅，不是过关）`  
4. **TRACK_INTRO** 加一句：后面章节是按需查阅，不是第二遍教科书。

课文与 `groupOrder` **可以暂时不改**。入口是 `/#/paths/fullstack` 与 `/#/paths/architect`。侧栏已有「交付 / 架构 / 索引」；交付和架构模式下进度按必读节数，并写明毕业看交付。

## 7. 审查附录（2026-10-09）

与 [架构师主线设计.md](./架构师主线设计.md) 第 7 节同一次核对。结论维持：**课文保持；默认「刷完即毕业」不保持。**

| 发现 | 处理 |
| --- | --- |
| F1 写成「≈ D1+D2」，和架构师关卡 2 的并发/幂等套件抢定义 | F1 只对齐 D1；幂等套件留在 F3 或升级到 D2 |

| 课数 719、主线 8 课 id | 与 index 一致，未改 |

**审查后仍成立、不追加新路线：** 不删章节、不重写 `groupOrder`、不把索引线设毕业条件。10 年若生产竖切已能讲清四层与失败，可跳过重复的全栈刷课，但跳关卡 4 之前仍要用 D1～D3 的交付物自检，不能凭年限跳。
