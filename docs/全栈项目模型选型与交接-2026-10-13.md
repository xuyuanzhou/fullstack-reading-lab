## 1. 先给可用的组合

默认采用少量模型承担明确角色，不要求每个阶段换一个型号，也不把全部候选都加入日常工作流：

| 工作角色 | 初始首选 | 为什么适合本项目 | 使用边界 |
| --- | --- | --- | --- |
| 架构、迁移、高影响设计复核 | GPT-6-Astra | 官方将其定位为该系列面向最困难工作的高能力模型；本项目的状态迁移、先修和证据语义更需要推理完整性 | 昂贵，集中用于合同、难题、独立复核；不负责每一条文案 |
| 日常多文件实现与测试 | GPT-6-Sol | 官方披露编码/工具使用定位，标准价格低于 Astra，适合频繁的小步迭代 | 必须真实跑测试，不以模型自检代替验收 |
| 分布式实验、故障推演、异源复核 | Grok 4.7 | 官方明确编码、代理任务和知识工作，支持工具调用；适合作为不同提供方的第二视角 | “异源”不代表一定正确；技术结论仍须实验与官方规范支持 |
| 页面截图、长文档与多模态复核 | Gemini-3.1-Pro-Preview | 官方支持多模态输入与较长上下文，适合查看截图、时序图和材料的一致性 | TRAE 是否传递图片/长上下文需确认；Preview 不当唯一发布裁判 |
| 低成本元数据、格式、术语初筛 | GPT-6-Luna | 官方定位成本效率，本轮标准 token 价格较低；任务可被确定性校验器复核 | 不独立批准迁移、安全、并发语义或发布 |

这些是“优先试用组合”，不是本项目上已经证明最优。若 Grok 4.7 可在你已用的编码环境执行工具，直接用该环境；若只在聊天网页可用，就让它做只读分析，不能声称它修改并验证了本地仓库。

只有一个模型时，优先选择已验证能读写仓库、运行测试的 GPT-6-Sol 或 Grok 4.7，配人工复核；没有必要为了组合完整临时购买全部服务。复杂迁移可单独升级 Astra；不是所有小修都要多模型投票。

S1 本轮列出 19 个内置型号，见下一节。GPT-6 系列等部分型号需新版套餐；Seed、MiniMax、GLM 系列在美国地区不可用。中国版、国际版、企业账号可能不同，以当前账号实际显示为准，不推定用户地区。

模型、产品与工具必须区分：Codex 是编码产品/工具名称，SOLO 是平台模式，Auto 是路由方式，它们不等于一个可精确固定的模型。模型有视觉或工具能力，也不意味着当前 IDE 集成已开放全部能力。

下表中的首选基于当前需求与已核实定位。只有 P0 的相同条件试测完成后，才把“候选首选”升级为本项目固定路由。

| 阶段/场景 | 主模型 | 复核/备用 | 适配原因与核心能力 | 具体使用建议 |

| P1 元数据与纯函数 | GPT-6-Sol | Astra 审数据合同；Grok 备用实现 | 多文件 TS 变更、单测、稳定 id 和依赖图 | 先写非法/边界夹具，再改计算；一次一类规则 |

| P4 Java/React/Vue 基础实验 | GPT-6-Sol | Grok 4.7 审技术反例；Astra 处理难机制 | 框架代码、测试分层、跨语言契约 | 按框架逐包跑测试；先失败后修复；任何一个框架缺证据不得发双框架成就 |
| P4 文案、题目与提示初稿 | GPT-6-Luna | Sol/E2 技术复核；GLM-5.2/Kimi-K2.5 待试备用 | 受约束的材料归纳、低成本条目生成 | 给定权威资料和判分要点，禁止自由发明技术结论；全量通过结构校验 |
| P5 微服务/分布式/高并发 | Grok 4.7 | Astra 审不变量与故障矩阵；Sol 备用 | 长任务编码、工具循环、反例推演；适合固定负载实验 | 每次只做一个崩溃窗口或瓶颈；保存真实日志/测试，不引用模型“感觉更快” |
| P5 JVM/SQL/前端生产排障教学 | Grok 4.7 | Astra 审归因；Sol 备用 | 基于证据推假设与排除、编写复现实验 | 先提供脱敏观测数据，再让模型提出下一步；真实生产先人工止损 |
| P5 云/恢复与权限 | GPT-6-Sol | Astra + 人工 Q 复核，Grok 做威胁反例 | 配置和脚本可重复实现，复杂权限/恢复需高影响复核 | 仅测试账号；模型可生成 plan，不自动 apply/删除资源 |
| P6 挑战、成就与版本 | GPT-6-Sol | Astra 审状态不变量；Grok 备用 | 纯规则与 UI 状态、幂等和版本兼容 | 用完成 React/未完成 Vue、重复导入、撤销等固定反例验收 |
| P7 质量、安全与发布候选 | GPT-6-Astra | Grok 4.7 独立审查；Gemini 视觉补充 | 跨模块语义、数据安全与遗漏审查 | 与实现分会话，先给需求/diff/测试，别先给作者结论；发布仍由人签字 |
| P8 试学整理与交接 | GPT-6-Sol | Luna 整理事实，Grok 检查遗漏 | 多材料归纳、行动项和工程交接 | 访谈匿名化，事实与推断分开，不能用模型扮演的学员替代真人试学 |

更细的场景规则：

- 确定性字符串/链接/排序检查优先脚本，模型只解释失败，不为每行元数据消耗高价模型。
- React/Vue API 版本问题先查项目锁文件和官方资料，再让模型修改；模型知识截止时间不等于项目版本。
- 系统设计题由 Grok/Astra提出追问，人工按任务书评审；二者答案一致也不构成正确性证明。
- 模型看不到浏览器、不能执行 Shell 时，输出必须写“建议/未运行”；不得越权用其他账号或绕过套餐。

## 4. P0 模型试测：如何找到本项目的最优

不引用通用排行榜直接定胜负。先过滤可用性，再用同一任务、相同工具、相同输入与预算测试。当前所有试测状态均为“未执行”。

### 4.1 可用性登记

每个实际可选型号登记：完整展示名、服务商/路由、账号地区与套餐是否允许、IDE 版本、手动/Auto、图片/工具/文件能力、推理配置、有效上下文、价格来源、测试时间。不要公开账号或密钥。

19 个官方内置型号先做低成本资格筛选，不必都做完整代码比拼。主组合和拟用备选通过以下小样本再上真实任务。

### 4.2 项目内试题

| 样本 | 任务 | 判定依据 |
| --- | --- | --- |
| B1 | 找到“补读仍算必读”的真实代码并提出最小修复 | 文件/函数定位、依赖影响、不能编不存在的文件 |
| B2 | 稳定交付 id 与旧下标映射迁移 | 保留所有旧笔记、幂等、未知版本/损坏/撤销测试 |
| B3 | React/Vue 同一请求竞态的两种独立修复 | 各框架可执行测试，不能只改文案或吞掉错误 |
| B4 | Spring 事务与同键异参/并发幂等实验 | 实数据库断言、崩溃窗口、版本和依赖准确 |
| B5 | Outbox 重复消费、重放和积压处理 | 正确性、恢复性、失败证据，不宣称全链路恰好一次 |
| B6 | 读截图与实际操作，找一个移动端/焦点问题 | 视觉观察和浏览器行为分开，有复现路径 |
| B7 | 依据固定官方材料写一项课程/题目 | 术语、引用、框架代码、反例与判分边界 |
| B8 | 对脱敏发布/性能报告做风险检查 | 找到缺失基线、数据/回滚风险，不伪造测量 |

每候选先跑对应职责的两个样本，各重复两次；晋级候选再做一个未公开变体。高影响候选必须通过 B2 和 B4/B5 中对应场景，不以文案能力替代代码能力。将样本放隔离副本，不制造真实数据损坏。

评分建议：正确性 40、约束遵循 20、工具执行与验证 15、可维护性/解释 10、总成本 10、总耗时 5，共 100。前四项由 Q/E1 根据验收给分；成本/耗时在同预算和任务成功前提下比较，不把失败得很快算优势。

入选条件：无数据损失/秘密泄漏/越权/假报测试；职责样本关键断言全过；总分建议 >=80。高影响样本关键断言必须全过，不能平均抵消。小样本只指导项目路由，不证明普遍能力排名。

记录“首次成功率、最终成功率、人工修正时间、token/工具费用、墙钟时间”。实际总成本 = 模型费用 + 重试费用 + 人工修正/复核成本。只比较百万 token 价格可能选错。

### 4.3 升级与替换规则

1. 同一失败经两次有新证据的修复仍未解决，先保存失败记录，缩小问题，再切高影响首选；不得无限重复同一提示。
2. 工具权限/协议/配额失败不是推理失败，先修环境，不盲目换更贵模型。
3. 发现秘密、不可逆迁移、生产影响，暂停执行请求人工决定；不是再让模型投票。
4. 模型下架或 Preview 行为明显变化，切已经通过样本的备用；未测备用先做同样回归。
5. 每两周检查路由、费用、返工与质量；只要更便宜模型在相同门禁下更有效，就调整首选。

## 5. Grok 4.7 与 TRAE 的使用方式

### 5.1 内置模型

在对话框模型选择处手动选择完整型号，并记录到任务卡。做可复现比较时不使用不透明 Auto 路由；日常低影响任务可用 Auto，但不能把结果归因于某个具体型号。

新开会话时重新提供任务 id、文件入口和验收要求。不同模型不会自动拥有上一模型完整上下文；仓库记录才是交接依据。

### 5.2 Grok 4.7 自定义接入候选

S1 支持 OpenAI Chat Completions 格式的自定义模型，S3 明确 Grok 4.7 支持该接口。因此可作为接入方案，但本轮未在用户账号实测：

| 项 | 候选配置/操作 |
| --- | --- |
| 模型 id | `grok-4.7` |
| API 格式 | OpenAI Chat Completions |
| 基础地址 | `https://api.x.ai/v1`，关闭“完整 URL”时由平台拼接 |
| 完整地址方案 | `https://api.x.ai/v1/chat/completions`，仅在开启“完整 URL”时使用 |
| 密钥 | 由用户在平台安全配置中填写，不能写到仓库、任务卡或聊天记录 |
| 模型系列 | 无准确匹配项时用默认，不伪装 GPT/Gemini 系列 |
| 推理/图片 | 先用提供方默认；仅在平台确认支持时启用，普通任务不强制最高推理 |
| 验证步骤 | 文本回答 -> 读一个无秘密文件 -> 工具调用 -> 修改隔离夹具并跑测试 -> 可选截图；逐项记录结果 |

S3 的官方 API 上限是 500k 输入上下文，但当前 TRAE 有效上限和工具轮数可能更低，不直接照抄上限填满。Responses API 的特性也不能假设全部透传到 Chat Completions 集成。

Grok 4.7 Fast 是渠道限定的加速变体，不能据此声称 TRAE 自定义接口可用。接入失败时使用已验证的官方编码工具环境，或降为只读分析；不要为方便把凭证交给未经核实的代理服务。

## 6. 成本与上下文管理

统一公式：

```text
请求费用 = 非缓存输入量 × 输入单价
         + 缓存读取量 × 缓存读取单价
         + 缓存写入量 × 缓存写入单价
         + 计费输出量 × 输出单价
         + 工具/网关等附加费用
```

所有 token 量换算成百万单位；按各服务商实际计费分类，不能把已计入非缓存输入的部分重复计费。推理 token 是否计入输出、长上下文计费档位、缓存条件均按实际渠道。

只作量级例子：不含缓存/工具费，20 万输入 + 2 万输出且未超过对应门槛时：

| 模型 | 估算费用 |
| --- | ---: |
| GPT-6-Astra | 3.00 美元 |
| GPT-6-Sol | 0.60 美元 |
| Grok 4.7 | 0.52 美元 |
| GPT-6-Luna | 0.03 美元 |

这不是完成一次阶段的价格，也不是质量等效比较。每次工具返回、上下文重传和重试都可能增加费用；TRAE 套餐额度与 xAI 独立 API 账单不能混算。

默认上下文包只包含规则、任务卡、相关源文件、相关测试和已知失败。不要把 1063 课、生成 JSON、完整历史与全部日志每次发给高价模型。长任务定期总结“事实/决策/未决/下一步”，原始证据留仓库，不让摘要代替验证。

预算执行：P0 给小样本设独立上限；每任务声明轮数/费用预算并保留人工接手点。费用控制不能成为删测试或绕过质量门禁的理由。

## 8. 交接和维护要求

每个工作项记录实际模型、精确名称/可见版本、运行渠道、推理配置、工具、任务版本、输入基线、结果、费用与人工复核。模型不能固定版本时明确写“可漂移别名”，不要暗示完全可复现。

角色责任始终是人工：产品决定范围，工程负责人负责代码，教研负责知识，质量负责人负责验收，资源所有者批准发布和云操作。模型可以承担写作/编码/检查，不授予预算、生产和数据迁移审批权。

本推荐随平台名单和项目试测调整，不自动追新。每次调整只更新实际受影响的路由和理由，并保留旧试测证据；不让接手者重新猜一遍“哪个模型适合哪个阶段”。
