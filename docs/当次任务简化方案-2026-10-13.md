## 1. 现在实际在做什么

当次任务是路线页上的一张卡片。数据在浏览器里，类型在 `web/src/state/learningEvidence.ts`。三道题在 `web/src/data/learningTasks.ts`。页面在 `web/src/components/learning/CurrentTask.tsx`。

学员要完成的事只有一件：对着一道题写下自己的观察，必要时指出哪一条预期没有成立。本站不运行 `labs/order-g1g2` 的 Maven。学员自己写下的内容，读入后 `verification` 保持 `pending`，不能因为文本里写了「通过」就变成已通过。关卡勾选仍是自评。

现在卡片上的动作是：

```text
按 15/30/60 换题
  -> 记为已开始          写入 attempt.status = started
  -> 选择一条没成立
  -> 记下没成立          再要求 status 已是 started 或 failed，写入 failed 和一条证据
  -> 另记一次            新 attempt，status = started，清空草稿
  -> 继续这一题          把同一条 failed 改回 started
  -> 保存写下的内容      再写一条来源为学员自己的证据
  -> 导出记录            把整份信封显示在文本框
  -> 检查能否导入        解析刚才那段文本，不写入
  -> 一天后 / 一周后 / 一个月后回来
展开参考答案             不写记录
```

一次观察最多写三次进度：开始、失败、保存。三次都进 `localStorage`，并各加一次 `revision`。

## 2. 冗余和站不住的结构

### 2.1 开始不是业务步骤

`记为已开始` 不运行命令，也不产生证据。它只为了让下一次点击通过组件里的判断：没有 `started` 或 `failed`，就不能记下没成立。`learningEvidence.ts` 本身允许直接写入 `failed`。`scripts/learning-platform.test.mjs` 的失败用例也是直接构造 `failed`，不经过 `started`。

这个状态把「我去本机跑了命令」和「页面允许记一笔」绑在一起。学员没按开始时，写下的结果无法记成未通过。

### 2.2 两条路都在保存同一段文字

`记下没成立` 和 `保存写下的内容` 都把草稿写成来源 `self`、复核 `pending` 的证据。差别只是前者多一个测试名。学员要先判断该按哪一颗，才能把同一段话留下。

`继续这一题` 和 `另记一次` 也重叠。前者把同一条尝试从 `failed` 改回 `started`。后者新建一条尝试并保留旧证据。产品要的是「未通过记录还在」。新建尝试已经满足。把状态改回去不增加新的观察。

### 2.3 导入按钮没有写入

`检查能否导入` 只调用 `previewImport`。文本框是只读的，内容就是刚导出的那一份。没有确认写入。按钮位于做题路径上，结果却是「可以导入，但没有合并」。

导出可以留。导入预览属于整份学习记录的恢复，不属于这一道题。

### 2.4 用时被当成任务主键

换题用 `estimatedMinutes` 查找。`15 | 30 | 60` 各只能有一道题。再加一道 30 分钟题，两颗按钮会指向不确定的那一条。时长是预估，任务身份是 `id` 加 `version`。

打开路线页时，卡片固定从 30 分钟题开始，不看学员正在看的关，也不看未写完的草稿。

### 2.5 暂停的三种时长没有改变回来后的题

一天、一周、一个月都只写入 `pause.choice`。继续时固定 `choose(15)`。三种按钮的记录效果相同：草稿和证据都还在，回来看 15 分钟那题。时长需要保留，因为设计要求能标出离开多久；它不该是三颗和保存并列的主按钮。

### 2.6 卡片承担了存储规则

`CurrentTask` 同时生成尝试 id、决定状态机、调用证据函数、预览导入、切换暂停。`hintLevel` 在每次写入时都是 `0`。类型里的 `saved` 页面从不使用。通过与否的规则已经在 `rememberEvidence`：来源是 `self` 时强制 `pending`。页面再反复写「待复核」，不能加强这条规则。

参考答案和「哪一条没有成立」说的是同一组事实。答案负责说明什么应当发生。选择负责让学员标记自己看到的哪一条没有发生。两块都要留，但不能再各配一套动作按钮。

## 3. 留下的需求

下列行为已经有测试或总计划条款，简化时保持不变。

| 需求 | 现在落在哪 |
| --- | --- |
| 课程和九关地图随时能打开 | 路线页不锁课 |
| 一次只呈现一道题 | 卡片只渲染 `task` |
| 本站不运行 Maven | 命令只显示 |
| 学员自述不能变成已通过 | `rememberEvidence` 把 `self` 收成 `pending` |
| 阅读和关卡勾选不是通过 | `verifiedFromReading` 返回空；勾选进 `selfChecks` |
| 未通过记录在再写一次后还在 | 新尝试不删旧证据 |
| 暂停不删草稿和证据 | `pause` 只改 `pause` 字段 |
| 回来从 15 分钟那题看起 | 现有继续逻辑 |
| 人工题可记 0～4，来源是学员自己 | `selfEvidenceForDraft` |
| 更旧的页面不能改写更新的记录 | `schemaVersion` 更高时只读 |
| 已删除的尝试不会被导入复活 | 合并比较 `deleted` |
| 参考答案默认收起，展开不写证据 | 卡片上的 `details` |
| 交付物 id 顺序不变 | `FROZEN_DELIVERABLES` |

不在这次简化里做的：在线运行测试、把日志文本升级为 `local` 通过、成就、关卡解锁、新的 `schemaVersion`。

## 4. 简化后的任务流程

```text
打开路线
  -> 有未写完的尝试：打开那道题
  -> 否则：打开 15 分钟「写下这一笔订单的四段职责」
学员换题（按任务 id，分钟只是题名旁的字）
学员阅读目标、输入、完成条件、提示
学员可展开参考答案（不写记录）
有本机命令时，自己在样板目录运行
在一个文本框写下看到的结果
若某条预期没有成立，选中那一条
按一次「保存这一次」
  -> 没选预期：attempt 为 draft，证据用 selfEvidenceForDraft
  -> 选了预期且文字非空：attempt 为 failed，证据用 labFailureEvidence
想再观察一遍：按「再写一次」
  -> 新 id，草稿清空，旧证据保留
先离开：在同一菜单里选一天、一周或一个月
  -> 只写 pause
  -> 继续时清除 pause，打开 15 分钟那题
复制整份记录：一个动作，文本出现在卡片下方
```

主路径上的写入按钮是两颗：`保存这一次`、`再写一次`。离开和复制记录收在主路径下面。

`started` 不再由新操作产生。已经存在的 `started` 记录仍能读：页面把它显示成「这一次还没有记下结果」，保存时按上面的规则改成 `draft` 或 `failed`。不为此提升 `schemaVersion`。

## 5. 技术实现路径

仍是静态站点加 `localStorage`。不增加服务，不把 Maven 放进浏览器。

| 层 | 保持 | 调整 |
| --- | --- | --- |
| `learningEvidence.ts` | 规范化、`pending` 强制、合并、暂停、导出、导入预览 | 不改函数契约。页面少调用，不是另写一套存储 |
| `learningTasks.ts` | `id`、`version`、`answer`、`lab` | 换题查找从「按分钟」改为「按 id」。分钟只显示 |
| `CurrentTask.tsx` | 展示一道题、命令、答案、文本框 | 删除开始、继续、单独的失败按钮、导入预览。保存函数按有没有选中预期调用现成的两个证据函数 |
| 进度恢复 | `previewImport` 仍可用 | 从当次任务卡片移出，留在后续的记录恢复入口。本次可以先不放按钮 |

尝试 id 维持现有形状：第一次 `${taskId}@${version}`，再写一次在后面加 `#` 和序号。失败证据 id 仍由 `labFailureEvidence` 生成。这样旧记录和新记录能放在同一信封里合并。

`hintLevel` 继续写 `0`，直到真的有分层提示。不删字段，避免旧记录规范化时丢值。

任务增加时只追加 `LEARNING_TASKS` 的一项，带稳定 `id`。不要再占一个新的分钟档。一道题若没有 `lab`，保存只走草稿证据。有 `lab` 时，没选预期仍可保存草稿；选了预期才记未通过。

参考答案继续放在收起的 `details` 里。展开不调用 `saveLearningDraft`。

## 6. 核心功能怎样算做完

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| F1 | 打开路线，不点保存 | `attempts` 与 `evidence` 条数不变 |
| F2 | 15 分钟题写下文字并保存，自评 0～4 | 一条 `draft` 尝试；一条证据 `source = self`、`verification = pending`；分数来源是 `self`；`taskVerified` 为 false |
| F3 | 30 分钟题选中一条预期，写下结果，保存一次 | 一条 `failed` 尝试；证据摘要含该检查 id；`verification = pending`；不出现第二条「开始」尝试 |
| F4 | 在 F3 之后再写一次 | 尝试变为两条；证据仍是一条；新草稿为空 |
| F5 | 展开参考答案后刷新 | 证据条数与展开前相同 |
| F6 | 先离开，选一周 | `pause.choice = week`；尝试和证据与离开前相同；页面仍可打开课程 |
| F7 | 从暂停继续 | `pause` 为空；当前题是 `g1.write-path`；记录条数不减少 |
| F8 | 记录 `schemaVersion` 高于页面 | 只读，保存不改写 |
| F9 | 页面文本或导出的 JSON 里把 verification 写成 passed，且 source 为 self | 读回后仍是 `pending` |
| F10 | 复制记录 | 文本能被 `previewImport` 解析；这个动作本身不增加证据 |

性能要求沿用现有页面，不单为这张卡片定新的服务指标。当次任务不发网络请求，不执行 Maven，不在切换题目时跑整份课表脚本。一次保存只写一次进度。比较基线是现在的「开始 + 记下没成立 + 保存」三次写入；简化后同一次观察只写一次。

## 7. 验证计划

实现时按这个顺序查。未改存储函数之前，现有测试就应保持通过。

```bash
cd web && npm test
cd web && npx tsc --noEmit -p tsconfig.app.json
```

`npm test` 里与本方案直接相关、实现后仍须通过的用例：

- `a self-report stays pending, and reading does not create a pass`
- `a recorded lab failure stays pending, and retry keeps it`
- `pause keeps the draft and evidence, and an unknown pause is dropped`
- `a deleted attempt is not restored by another tab or an import`
- `corrupt and future records stay readable without being rewritten as empty success`
- `frozen deliverable ids match the current output order`

存储函数不改时，这些用例不需要改断言。若实现时改了 `labFailureEvidence` 或 `rememberEvidence`，先停止，回到第 3 节的表。

浏览器手工核对 ` /paths`：

1. 默认或继续后看到 15 分钟题，没有本机命令，有自评 0～4。
2. 换到 30 分钟题，命令仍是 `cd labs/order-g1g2 && ./mvnw -s maven-settings.xml test`。页面不发起该命令。
3. 走 F3、F4。证据列表只有未通过那一条，状态是待复核。关卡交付勾选数字不变。
4. 换到 60 分钟题，三条预期都在，参考答案写的是同一幂等键第二次返回第一次的订单。
5. 走 F6、F7。
6. 手机宽度下保存和再写一次的点按高度至少 44px，卡片不把页面撑出横向滚动。
7. 系统读屏仍是后续项：按钮名称要读出动作和结果，参考答案收起时不把全文当成立即可见的通过结论。

已知限制写进实现时的变更记录：本站不能证明学员真的跑过 Maven；复制出的 JSON 被改掉后，自述来源依然是待复核。

## 8. 可行、稳定、可扩展

可行：不新依赖，不迁移旧信封。保存仍调用已经测试过的 `selfEvidenceForDraft` 和 `labFailureEvidence`。

稳定：旧的 `started` 记录能显示、能接着保存。更高的 `schemaVersion` 仍只读。删除标记和合并规则不动。`FROZEN_DELIVERABLES` 的顺序不动。

可扩展：下一道题是数组里的新 `id`。有命令就带 `lab.checks`，没有就只保存草稿。等真的有本站可重跑的检查，再使用已有的 `kind: local-check` 与 `source: local`。那是另一条证据，不从这次的自述升级而来。

## 9. 实现顺序

1. 只改 `CurrentTask` 的按钮和保存分支。存储函数和测试断言不动。
2. 换题改为按 `task.id`。默认题改为未完成尝试，没有则用 `g1.write-path`。
3. 确认第 7 节命令和浏览器清单。
4. 导入预览若还要做，放到记录恢复，不放回这张卡片。

第 1 步就可以去掉开始、继续、单独的失败按钮和导入按钮。第 2 步才解除「一个分钟档一道题」的限制。
