## 1. 项目范围与完成定义

### 1.1 做什么，不做什么

这是一项“学习产品 + 教学实验”的建设项目，不是要求学习者在 20 周内掌握所有技术。学员的 1060～1500 基础学时和开发团队的实施人时是两套口径。

| 工作包 | 必须交付 | 边界 |
| --- | --- | --- |
| 课程组织 | 预备阶段、九关、能力依赖、既有课程复用与缺口补充 | 不重写全部 1063 课，不用课数证明完成 |
| 学习体验 | 当次任务、可选挑战、进度、成就、反馈、暂停恢复 | 不锁全文，不做签到惩罚、排行榜或积分商城 |
| 能力验收 | 笔试、实验、口述、证据来源和任务版本 | 本地测试与自评是首版；不冒充在线自动认证 |
| 实验工程 | Java 服务、React/Vue 双端、数据/安全/分布式/排障/云部署 | 同一业务演进，框架实验可单独运行，不要求学员启动全部中间件 |
| 交付运营 | CI、测试、迁移、回滚、公开部署、试学和维护手册 | 不自动购买云服务或开放生产权限 |
| 后续扩展 | 跨设备同步、在线隔离执行、AI 助教 | 独立立项与安全验收，不计入本次 20 周基线 |

完成标准：每个必修能力都有课程或正式参考资料、先修、任务、可运行正反例或明确人工评分办法；产品正确保留旧进度；所有发布门禁通过；试学问题得到处置；接手者能按文档复现。没有实验代码只有任务描述时，不能把内容包标已交付。

### 1.2 当前基线

- 产品是 `web/` 下 React 19、TypeScript、Vite、Ant Design 静态网站，不存在完成版 Java 平台后端。
- 课程源在 `curriculum/`，经 `scripts/export-curriculum.mjs` 导出；不要手改导出 JSON 作为源内容。
- `masteryGates.ts`/`learningPaths.ts` 定义九关；`GateDock.tsx`/`PathPage.tsx` 展示流程；`sideTracks.ts` 是静态补强入口。
- `progressStorage.ts` 在原有规范化、多标签合并和异常存储上增加了 `learning` 信封。关卡是否通过仍看 `pathChecks`，不看这份信封。
- `scripts/architecture.test.mjs` 已验证损坏旧数据、部分并发笔记和存储错误。`scripts/learning-platform.test.mjs` 覆盖旧勾选迁移、备份、未来版本只读和撤销不被并集复活。这还不能证明成就或新任务解锁。
- `web/package.json` 已有 `test`、`lint`、`verify:committed`、`check`；lint 使用 oxlint，不为规划一致性强换 ESLint。
- PR 工作流运行 `verify:committed` 和本机阅读器测试；Pages 在主分支推送时运行完整构建后部署。PR 当前不等同于已运行 Vite 完整构建或浏览器回归。
- 工作区已有其他会话未提交变更。P0 先明确归属和基线，不覆盖、不批量提交、不用清理命令重置。

## 2. 实施架构与数据流

```text
培养方案 / 能力矩阵
  -> 课程源 + 任务元数据 + 实验工程
  -> 静态校验 / 导出 / 内容与实验测试
  -> React 学习网站（任务、提示、证据、能力状态）
  -> 本地学习记录（版本化、可导出、可恢复）

独立实验：React/Vue 前端 -> Java 服务 -> 数据库/缓存/MQ
实验结果 -> 学员登记或经明确的本地检查导入 -> 待复核证据
```

规划新增位置，创建前确认仓库已有结构并再评审：

| 位置 | 职责 |
| --- | --- |
| `web/src/data/learningTasks.ts` | 任务 id、版本、能力、先修、评分规则；不存大型参考实现 |
| `web/src/data/learningSkills.ts` | 能力与课程/任务对应关系 |
| `web/src/state/learningEvidence.ts` | 证据规范化、纯状态计算和迁移函数 |
| `web/src/components/learning/` | 任务卡、尝试、反馈、证据、成就；复用标准组件 |
| `labs/fullstack/` | Java/React/Vue 主实验、固定依赖与按阶段启动说明 |
| `labs/scenarios/` | 故障/压测/恢复与双框架小实验 |
| `docs/project-execution/` | 迭代任务卡、风险、基线报告、发布和模型试测记录 |
| `scripts/learning-path.test.mjs` 等 | 数据校验、进度迁移/解锁规则测试；名称最终随实现确定 |

这些路径是建议，不是已经存在。不要把 Java/MQ/Kubernetes 部署进学习网站的静态托管环境。G8 的“云上交付”是实验系统的部署，学习站本身仍可用 GitHub Pages。

数据约束：

1. 课程、关卡、任务、交付物、能力、成就均使用稳定 id；评分规则改变时增加版本。
2. 课程必需/补读与替代组用显式字段；React 与 Vue 的能力为全部满足，MQ 工具选择可为任一满足。
3. `done` 只是阅读；旧 `pathChecks` 只是自评；有测试/评审证据才进入相应验证状态。
4. 存储信封的 schemaVersion 与并发 revision 分开；不按数组位置解释新交付物。
5. 大型日志、堆转储和敏感源码不塞进 localStorage；只保留脱敏摘要与受控引用。
6. 预留后端同步接口不等于首版需要数据库服务；本地记录不宣称防作弊认证。

## 3. 人员、设备与预算

### 3.1 资源基线

每周有效投入 80 人时。它是合计容量，不是让一人每周工作 80 小时。

| 角色 | 每周人时 | 主要责任 |
| --- | ---: | --- |
| 前端/全栈工程负责人 E1 | 30 | 网站、任务模型、存储迁移、前端实验、集成 |
| Java/课程实验工程负责人 E2 | 30 | Java、数据库、分布式、排障与云实验、技术讲解 |
| 兼职质量与安全复核 Q | 10 | 测试设计、关键反例、兼容/浏览器/恢复验收 |
| 产品与教研负责人 P | 6 | 范围、难度、任务拆解、试学、发布签字 |
| 交互与可访问性支持 D | 4 | 标准组件流程、焦点、反馈、移动端试用 |
| 合计 | 80 | 每周排 64 人时任务，留 16 人时缓冲 |

多人角色可由少数人兼任，但同一小时不能重复计算。若只有一个人，必须重新排期，关键数据迁移/安全验收至少找一次外部复核；模型能辅助，不能充当责任人或真实学员。

| 环境 | 最低可用配置/要求 | 建议与控制 |
| --- | --- | --- |
| 网站开发 | 当前 Node 22 工作流兼容的具体小版本、锁文件、浏览器 | P0 固定版本；现有 Node 原生 TS 测试开关也要能运行 |
| Java 实验 | JDK 21 基线、Maven Wrapper、容器运行时 | Boot/Cloud 按兼容矩阵锁定；不要自动升级所有依赖 |
| 普通实验机器 | 16GB 内存可按 profile 分开启动 | 推荐 32GB；MQ/搜索/观测不同时强制启动，配置资源上限 |
| CI | Linux runner；网站和实验分作业、复用缓存 | 浏览器/容器启动较重，PR 精选回归，夜间全量；保留失败产物 |
| 云实验 | 独立测试账号、最小权限、预算提醒、合成数据 | 默认销毁临时资源；不要给模型生产或账单管理权限 |
| 测试资源 | 桌面/移动视口、至少两类浏览器引擎、键盘/读屏检查 | 5～8 名试学者，分别包含新手、有前端经验、有 Java 经验 |

### 3.2 费用估算

首版开发工作量 1280 人时，缓冲 320 人时，总计划容量 1600 人时。人力成本 = 各角色实际投入 × 其时薪；不虚构统一市场报价。

非人力建议先批准每月试行上限：模型/接口 100～300 美元、测试云资源 30～150 美元、额外 CI/存储 0～50 美元；这是自设预算范围，不是服务商价格承诺。前两周据真实账单调整，未获授权不启用自动超额消费。模型详细价格口径见选型文档。

资源触发规则：单实验超过机器内存预算时拆 profile；预计月支出达到上限 70% 时复核，90% 时停止非必要跑批；不能为了省钱取消数据恢复或授权测试。

## 5. 各阶段执行卡

每张卡的负责人是人工角色；建议模型见配套文档同名阶段。任务 id 可直接用于后续会话，不要求一次完成整个阶段。

### P0：启动与基线，W1，64 人时

核心目标：明确真实现状、可用资源、首版范围和可重复验证的起点。负责人 P/E1，Q 复核。

- [x] P0-01：读取规则与最近记录，登记工作区已有修改的文件/归属；选定受保护基线，不清理他人变更。登记见 [P0-01 基线](./project-execution/2026-10-13-p0-01-baseline.md)。
- [x] P0-02：对照完整能力矩阵逐项标“已有课程/缺实验/缺内容/需核实”，优先 Java、React、Vue 与数据安全。登记见 [P0-02 差距](./project-execution/2026-10-13-p0-02-capability-gap.md)。
- [x] P0-03：在隔离副本运行现有验证、完整构建，记录浏览器基线和既有失败；新失败和旧失败分开。结果见 [P0-03](./project-execution/2026-10-13-p0-03-baseline-verify.md)。
- [ ] P0-04：确认本地 Node/JDK/容器、云测试权限、账号可选模型；执行模型小样本试测，不读取或公开密钥。本机版本已记入 P0-03 报告；云权限和模型小样本未做。
- [x] P0-05：登记需求、非目标、负责人、预算、发布权限和未决事项，确认 M3 的范围。见同一份 P0-03 报告的需求节。

交付物：基线报告、能力差距表、资源/模型清单、需求验收表、首批任务卡。

核心目标：让课程、任务、能力和先修可计算、可校验。负责人 E1，E2/P 审核课程含义。

- [x] P1-01：冻结原 gate id；建立稳定交付物 id 与旧 `${gateId}:${index}` 对照表。见 `web/src/data/deliverableMap.ts`。

- [x] P1-04：重构 `slotsOf` 等纯计算函数，给空组、重复 id、悬空引用、依赖环、补读计数和替代组加测试。
- [x] P1-05：修改阶段文案前移除 `milestone.includes(...)` 这类隐式状态判定，改显式里程碑类型。

交付物：类型/数据合同、迁移映射快照、校验器、单测、相关 ADR（架构决策记录）。

验收：所有 id 可解析、依赖无环；补读不阻碍通过；保留原深链接；无法兼容的数据必须报可读错误。风险是排序变化使旧勾选错位，必须先冻结映射再改数据。

### P2：证据、状态与迁移，W4～W5，128 人时

核心目标：保留旧记录，区分阅读、自评、行为验证和人工评审。负责人 E1，Q 独立复核。

- [x] P2-01：在现有 normalize/read/write/merge 能力上增量扩展；独立 schemaVersion 与 revision。信封版本在 `learning.schemaVersion`，进度 `revision` 仍管多标签笔记。
- [x] P2-02：尝试和草稿写入 `learning.attempts`；保存草稿时另写一条来源为学员自己的证据，结果保持待复核。人工评分题可记 0～4 的自评，来源仍是学员自己。旧勾选只进 `selfChecks`。`verifiedFromReading` 固定返回空。本站仍不运行实验代码，所以页面不会把这条证据写成通过。
- [x] P2-03：迁移前备份、重复迁移幂等、迁移失败恢复、未知未来版本只读保护。备份键是 `${storageKey}.learning-backup`，已有备份不覆盖。
- [x] P2-04：多标签编辑/撤销明确冲突规则，不能用数组并集复活已撤销记录。任务草稿用删除标记。旧的 `pathChecks` 仍按并集合并。
- [x] P2-05：导出/导入预览、格式校验、配额失败、恢复提示；日志和导出不含秘密。查看导入只预览，不写入。

交付物：迁移函数、至少 12 类存储夹具、导出格式、数据兼容/回退说明、测试结果。

验收：旧阅读/笔记不丢失；旧勾选只成自评；损坏数据不白屏；撤销不会静默失效；失败显示未保存。风险是线上记录不可恢复，应对是灰度、独立备份键、旧版读兼容或明确恢复流程。

### P3：最小学习流程，W6～W8，96 人时

核心目标：用 G1/G2 样板验证“能开始、能得到反馈、能恢复”。负责人 E1，D/Q 复核。

- [x] P3-01：复用 `GateDock` 和标准组件，一次突出一个任务；选择 15/30/60 分钟。当次任务在路线页，关卡浮框仍是原来的 `GateDock`。
- [x] P3-02：任务详情呈现目标、前置能力、输入、完成条件、提示和证据入口。证据入口目前是草稿保存，不是实验日志。

## 6. 质量门禁与交付物标准

### 6.1 每张任务卡的完成定义

每项交付必须有：任务 id、负责人、基线、变更文件、需求到测试对应、可复现命令、预期/实际结果、已知限制、复核人、变更记录。模型自称完成不是证据。

| 质量域 | 发布门槛 | 失败时 |
| --- | --- | --- |
| 数据与迁移 | 所有迁移/撤销/恢复/未知版本夹具通过，旧笔记保留 | 停止推广新存储格式，修复后重放全夹具 |
| 正确性 | 核心不变量、权限、幂等、数据隔离负例全部通过 | 不允许以总体通过率抵消关键失败 |
| 内容 | 每必修能力有映射，课 id/依赖/术语/来源有效；框架代码真实 | 标未完成并阻止宣称该能力已交付 |
| 产品 | 解锁、反馈、成就、暂停恢复、双框架独立进度全覆盖 | 保持旧入口可用，不把坏流程强推给旧用户 |
| 安全 | 无秘密/私有资料泄漏、无任意代码执行、导入防异常 | 严重问题阻断发布，必要时撤下受影响产物 |
| 性能 | 固定设备/网络测试无相对基线 >20% 的未解释回退 | 定位/修复或由负责人说明取舍后批准；不是普遍行业阈值 |
| 可访问性 | 键盘完整主流程、可见焦点、读屏状态、减少动效 | 核心流程不可用则阻断，不能只看自动扫描 |
| 交接 | 独立启动/恢复/回滚演练成功，MD 与代码一致 | 不标阶段完成 |

计划新增的核心状态/迁移模块，建议语句覆盖 >=90%、分支 >=85%，同时必须有故意失败例和关键边界用例。覆盖率采集工具需在 P1 选定；仓库目前没有因此自动达标。实验看断言有效性，不追逐全库统一覆盖率。

### 6.2 已有验证入口与待补入口

在仓库根目录执行，以下是后续实施验证命令，不表示本次文档阶段全部运行过：

```bash
npm --prefix web ci
npm --prefix web run verify:committed
npm --prefix web run check
python3 -m unittest discover -s reader -p tests.py
git diff --check
```

`check` 会触发导出和构建，可能更新生成文件，应在隔离工作区或确认归属后运行。`verify:committed` 不代替完整构建和浏览器验证。

待补：任务元数据/迁移测试、浏览器回归、实验工程构建/测试、依赖扫描和恢复脚本。新增 Node 测试必须加入 `web/package.json` 的实际 test 命令，否则仅新建文件不会执行。Playwright 或等价工具在 P3 接入后再写成已可用命令。

## 8. 日常执行与跨模型接手

一次迭代一周，周初选择不超过容量的任务，周中检查依赖和风险，周末演示与复盘。每项任务推荐控制在 4～16 人时，大于 16 人时先拆分；不是让模型一次吞完整阶段。

交接材料最少包含：

1. “现在做什么/不做什么”与唯一任务 id。
2. `AGENTS.md`、契约、最近 3～5 条变更记录和本阶段入口。
3. 当前提交/补丁基线、允许文件、他人变更、不可变数据约束。
4. 验收用例和实际运行输出，失败项明确标未解决。
5. 决策、替代方案、风险、下一条可直接执行的任务。

模型选型、提示模板和升级规则在配套文档。没有专门授权时，不启动子代理、不让多个模型并发写共享工作区。规划里的多模型分工默认指用户顺序切换会话。

## 9. 扩展路线与变更控制

跨设备同步、用户账户、在线判题或 AI 助教不是“不做”，而是要单独计算成本和数据责任：

- 进入条件：首版稳定、明确用户需求、有人负责隐私与运行、预算批准。
- 另做身份/租户隔离、后端 API、冲突合并、数据删除、备份/灾备、滥用防护。
- 在线执行额外要求隔离、禁网/白名单、资源/时限、队列、审计、依赖镜像和安全评估。
- 初步预留 6～10 周重新估算的窗口，不计入 20 周首版，也不将该区间当已核定工期。

任何新增需求必须说明收益、影响任务、依赖、预算和验收。先更新此计划与变更记录，再调整代码；不得让下一模型自行扩大为全功能在线教育 SaaS。
