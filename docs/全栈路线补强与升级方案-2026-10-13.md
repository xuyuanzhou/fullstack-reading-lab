 九关主线不用推倒。它已经把一条真实业务做对、测住、排查、上线和留下决策这件事串起来了。

 要补的是四条过去只零散出现、但现在岗位普遍会问也普遍会用的侧线：

 原则：

 3. 求职默认看「主脊柱 + 2 条最贴岗位的侧线」；冲高级或架构再补齐 4 条。

 ## 4. 四条侧线

 ### A. 前端工程化侧线

 目标：从「会把页面做通」升级到「会交付、会维护、会讲取舍」。

 必补知识点：

 1. TypeScript：类型收窄、泛型、联合类型、接口与 schema 对齐
 2. React：组件边界、状态提升、Context、表单与验证、渲染性能
 3. Next.js：SSR、SSG、ISR、路由、服务端数据获取、缓存边界
 4. Node / BFF：聚合接口、鉴权转发、文件上传、环境变量
 5. 工具链：Vite、Webpack 基本认知，pnpm，Monorepo 基础
 6. 测试：Vitest / Jest、React Testing Library、Playwright
 7. 性能：Web Vitals、懒加载、拆包、缓存、图片与字体策略
 8. 可访问性：语义化、键盘操作、表单可达、颜色对比

 结束证据：

 - 一页带 SSR 或 BFF 的站点
 - 一组组件测试 + 一条浏览器端到端路径
 - 一份性能优化前后对比
 - 一份可访问性自查清单

 ### B. 云与平台侧线

 目标：从「会在本地跑」升级到「会在云上交付和运维」。

 必补知识点：

 1. Nginx / 网关 / 负载均衡：反向代理、转发、超时、限流入口
 2. 云基础：VPC、子网、安全组、负载均衡、域名、证书
 3. 对象存储与 CDN：静态资源、文件上传、签名 URL、缓存刷新
 4. 托管服务：RDS、Redis、消息队列、对象存储的边界
 5. Kubernetes 进阶：Helm、配置与密钥、资源配额、滚动发布
 6. IaC：Terraform 基础，环境参数化，避免手点控制台
 7. GitOps / 发布：Argo CD 或同类理念，蓝绿、金丝雀、灰度、回滚
 8. 灾备：备份、恢复演练、RPO、RTO、多可用区意识

 结束证据：

 - 一份云上部署图
 - 一次灰度或回滚演练记录
 - 一份备份恢复说明
 - 一份 IaC 或 Helm 的最小可运行样例

 ### C. 安全与合规侧线

 目标：从「知道几个 Web 攻击名词」升级到「能把安全要求落实到设计和代码里」。

 必补知识点：

 1. OAuth2、OIDC、Session、JWT 的适用边界
 2. RBAC、ABAC、对象级授权
 3. 输入与输出安全：SQL 注入、XSS、CSRF、SSRF、文件上传
 4. 秘钥治理：KMS、Secrets、轮换、最小权限
 5. 供应链安全：依赖扫描、镜像扫描、SAST / SCA 的基本做法
 6. 审计与脱敏：访问日志、操作日志、敏感字段遮罩
 7. 数据治理：保留期限、删除、导出、归档
 8. 合规入门：等保、GDPR、SOC 2、PCI-DSS 只要求知道边界，不硬背条文

 结束证据：

 - 一份威胁建模清单
 - 一组越权 / 注入 / 恶意上传测试
 - 一份日志脱敏与审计说明
 - 一份密钥与权限清单

 ### D. 协作与职业化侧线

 目标：从「能自己做完」升级到「能在团队里把事推进下去」。

 必补知识点：

 1. Git、分支、PR、Code Review、冲突处理
 2. 需求澄清、任务拆解、里程碑与风险说明
 3. RFC / ADR / 设计评审的写法
 4. Runbook、事故复盘、值班和升级路径
 5. 系统设计表达：容量、成本、边界、失败语义
 6. 项目讲述：背景、约束、决策、证据、收益
 7. 面试答辩：八股和项目要能对上，不靠背术语

 结束证据：

 - 一次完整 PR 和 Code Review 记录
 - 一份 RFC 或 ADR
 - 一份故障复盘
 - 一页系统设计讲稿或项目答辩提纲

 ## 5. 推荐学习顺序

 不是先刷完九关，再把四条侧线补一遍。推荐这样穿插：

 | 阶段 | 主线 | 侧线同步补强 |
 | --- | --- | --- |
 | 第 1 段 | 关卡 1～2 | 前端工程化 A1～A3；协作 D1 |
 | 第 2 段 | 关卡 3～4 | 安全 C1～C3；前端工程化 A4～A6 |
 | 第 3 段 | 关卡 5～6 | 协作 D2～D4；平台 B1 |
 | 第 4 段 | 关卡 7 | 数据补强、平台 B2～B4；安全 C4～C5 |
 | 第 5 段 | 关卡 8 | 平台 B5～B8；安全 C6～C7 |
 | 第 6 段 | 关卡 9 | 协作 D5～D7；求职答辩与项目讲述 |

 这样调整后：

 - 最小测试不再只在关卡 5 才第一次出现
 - 最小安全意识不再等到关卡 4 以后才想到
 - 云上交付不会等到最后才第一次碰控制面和发布策略

 ## 7. 项目集升级

 原来的作品 A / B / C 保留，再补一个项目 D。

 | 项目 | 目标 | 关键技术 | 交付证据 |

 若目标偏前端岗位，再加一个 `E`：

 - Next.js 内容站或管理台
 - 带 SSR / BFF / 组件测试 / 可访问性 / 性能对比

 ## 8. 求职与晋升时默认要能拿出的证据

 1. 一条完整业务的测试名和失败说明
 2. 一篇排查笔记
 3. 一篇 ADR 或 RFC
 4. 一次发布或回滚记录
 5. 一组权限 / 安全测试
 6. 一份系统设计讲稿
 7. 一页项目结果：性能、成本、稳定性或交付效率至少一个量化结果

 没有这些证据时，不要用「学过 Kubernetes」「懂分布式」「做过全栈」替代。
