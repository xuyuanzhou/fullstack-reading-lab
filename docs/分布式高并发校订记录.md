# 《分布式高并发》校订记录

核对对象是用户本机购买的 206 页《分布式高并发.pdf》。以下页码按 PDF 文件的物理页序号计算，可能与页脚印刷页码不同。本记录只提炼观点与纠错，不转录原文或复制原图。查阅日期：2026-10-01。结论是针对列出的表述，不代表全书每题均已审定。

| PDF 页码与主题 | 容易造成的误解 | 面向学习者的修正 | 对应公开课 / 核对依据 |
| --- | --- | --- | --- |
| 第 19 页，CAP | 把 CAP 当成脱离故障前提的“三选二”，或直接给数据库贴固定 CP/AP 标签。 | 先假设网络分区，定义具体读写操作及可用性要求，再描述阻塞、拒绝或允许暂时分歧的选择。CAP 的一致性不能和 ACID 的一致性混用。 | [CAP 课程](distributed-lessons.js)；[Gilbert–Lynch 论文](https://www.cs.princeton.edu/courses/archive/spr22/cos418/papers/cap.pdf) |
| 第 33 页，消息顺序 | 为了有序，一个 Topic 只能保留一个队列或分区。 | Kafka 只保证分区内的日志顺序；同一业务键稳定进入同一分区，其他键仍可并行。消费端的并行处理、失败重试和分区调整也要单独考虑。 | [Kafka 顺序课程](distributed-lessons.js)；[Apache Kafka 文档](https://kafka.apache.org/documentation/) |
| 第 71、77 页，XA / 2PC / 3PC | 把 3PC 归入 XA，或认为超时即可自动安全提交。 | XA 资源参与两阶段提交；3PC 是另一协议讨论。准备成功不等于最终提交，故障恢复必须处理未知决议与资源锁。 | [XA 课程](distributed-lessons.js)；[MySQL 8.4 XA 文档](https://dev.mysql.com/doc/refman/8.4/en/xa.html) |
| 第 79–82 页，布隆过滤器，含第 80 页图 | 通过对比两个 URL 的哈希值判断是否为布隆成员，或认为普通布隆位数组可直接删除。 | 对待查询元素计算多个位置，任一位置为 0 才能判定“不在集合”；全为 1 只能说“可能在”。清除共享位可能使其他元素出现假阴性。 | [布隆课程](distributed-lessons.js)；[Redis Bloom Filter](https://redis.io/docs/latest/develop/data-types/probabilistic/bloom-filter/)；[Redis Cuckoo Filter](https://redis.io/docs/latest/develop/data-types/probabilistic/cuckoo-filter/) |
| 第 25 页，缓存失效 | 将 TTL 抖动、锁和限流作为不分场景的万能组合。 | 区分批量过期、单热点失效与根本不存在的键，先测键分布、命中率及回源峰值，再选错峰过期、单次加载、空值缓存或限流。 | [缓存课程](distributed-lessons.js)；[Redis Cache Aside](https://redis.io/docs/latest/develop/use-cases/cache-aside/) |
| 第 89–91 页，限流 | 只给“每秒通过量”，忽略允许的突发。 | 令牌补充速率限制长期平均吞吐；桶容量决定可通过的瞬时突发。下游并发上限仍需要另设并发限制。 | [令牌桶课程](distributed-lessons.js)；[Redis Rate Limiter](https://redis.io/docs/latest/develop/use-cases/rate-limiter/) |
| 第 94 页，一致性哈希 | 以为虚拟节点同时解决节点倾斜和热点键。 | 虚拟节点有助于让键更均匀地映射到物理节点，单个高访问量键仍可能成为热点，需要复制、拆分或限流等机制。 | [一致性哈希课程](distributed-lessons.js)；[Karger 等论文](https://people.csail.mit.edu/karger/Papers/web.pdf) |
| 约第 27 页，消息解耦 | 库存挂了也不影响下单，只入队就返回成功。 | 入队只推迟扣减；卖出上限仍在。要有 Outbox、消费幂等与补偿、对账落到订单号。 | `distributed-mq-not-erase-invariant`；[Outbox](https://microservices.io/patterns/data/transactional-outbox.html) |
| 约第 17–18 页，REST | 插入写成 PUT；REST 收成只回 JSON。 | 服务分配 id 的创建常用 POST；PUT 是对已知 URI 的整份替换。JSON 前后端分离不等于方法语义。 | `http-create-post-not-put`；[MDN PUT](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Methods/PUT) |
| 约第 92 页，DNS 负载均衡 | 简单轮询 + 拧小 TTL 即实时。 | DNS 受解析缓存约束；实例摘流靠 LB。TTL 极小有流量代价。 | `dns-lb-not-just-round-robin`；[Nginx LB](https://nginx.org/en/docs/http/load_balancing.html) |
| 约第 201 页，Redis 锁 | setnx/get/getset 用本机时间判过期。 | 过期应由 Redis TTL；时钟偏差会双持有。 | `redis-lock-getset-wall-clock`；[Redis 分布式锁](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/) |
| 约第 200 页，MySQL 锁 | FOR UPDATE 当成跨机分布式锁。 | 行锁在当前事务连接上；长握锁撑连接池。 | `mysql-for-update-not-dist-lease`；[锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html) |
| 约第 32 页，消息幂等 | 删除一次和多次都是删掉，故天然幂等。 | 物理删主键终态常可幂等；软删/归还库存等重放可能再改状态。 | `mq-delete-not-always-idempotent` |
| 约第 13 页，CDN/反代 | 基本原理都是缓存。 | CDN 在边缘就近；反代在源站侧常做 TLS/选上游；缓存只是可选。 | `cdn-not-just-reverse-proxy-cache` |
| 约第 51 页，秒杀 JS | 控制 JS 一定不被 CDN 缓存。 | 需 Cache-Control 或 CDN 不缓存规则；开抢权威在服务端。 | `seckill-js-needs-cache-control` |
| 约第 49–52 页，客户端门闩 | Disable 按钮 / 藏 URL 防提前下单。 | 只能减噪音；服务端校验开始时间、限流与原子扣减。 | `seckill-client-gate-not-enough` |
| 约第 196 页，Redis 发号 | 五节点集群用初值 1..5、步长 5 并行发号，并当作去掉单点。 | 一个 INCR 键只在一个槽、一台主上；故障转移延续该计数。五段步长是五份钉死的计数器。 | `redis-cluster-incr-not-five-steps`；[Redis INCR](https://redis.io/docs/latest/commands/incr/) |
| 约第 57 页，NoSQL | 把 NoSQL 定义成最终一致、而非 ACID。 | NoSQL 是分类标签。单键原子、多文档事务、从库延迟要分开写。 | `nosql-label-not-eventual`；[MongoDB 事务](https://www.mongodb.com/docs/manual/core/transactions/) |
| 约第 68 页，拆分 | 单表数据到一千万以内就拆。 | 行数不是服务器限制。先测缓冲池、查询形态、复制与备份窗口。 | `mysql-split-not-at-ten-million`；[InnoDB 限制](https://dev.mysql.com/doc/refman/8.4/en/innodb-limits.html) |
| 约第 93 页，HTTP 重定向 LB | “比较简单”的 302 分流可当主负载均衡。 | 至少两跳；Location 常暴露后端，后续可绕过调度。主入口用反代/云 LB。 | `http-redirect-lb-two-hops`；[Nginx LB](https://nginx.org/en/docs/http/load_balancing.html) |
| 约第 202–205 页，配置中心 | 本地缓存 + 定时盲轮询即性能方案。 | 读多写少应变更通知/长轮询；本地缓存要版本与兜底。分钟级生效是窗口。 | `config-center-poll-needs-watch`；[Nacos 配置](https://nacos.io/docs/latest/guide/user/configuration/) |
| 约第 202 页，可重入身份 | MAC + 进程 ID + 线程 ID 标识持有者。 | 用随机 token；容器/PID 回收会撞车。 | `dist-lock-owner-not-mac-pid-tid`；[Redis 分布式锁](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/) |
| 约第 199 页，可重入需求 | 可重入锁（避免死锁）。 | 可重入只防同持有者自堵；交叉死锁靠顺序/超时，忘释放靠租约。 | `dist-lock-reentrant-not-deadlock-cure` |
| 约第 197–198 页，LRU | 标题“带过期时间”，正文只做容量 LRU。 | 容量淘汰与 TTL 是两维；未满时过期键仍应失效。 | `lru-capacity-not-ttl-expire`；[Redis Eviction](https://redis.io/docs/latest/develop/reference/eviction/) |
| 约第 19–20 页，BASE | 写成定理，并禁分布式事务。 | 工程口号；部分路径可最终一致，钱货仍要事务/Outbox/对账。 | `base-slogan-not-ban-tx`；[CAP 形式化](https://www.cs.princeton.edu/courses/archive/spr22/cos418/papers/cap.pdf) |
| 约第 105 页，禁止 JOIN | JOIN/大表子查询一律禁止，因一定临时表。 | 启发式；有索引联结可用 EXPLAIN 证明。勿逼出 N+1。 | `mysql-join-ban-not-absolute`；[MySQL JOIN](https://dev.mysql.com/doc/refman/8.4/en/join.html) |
| 约第 105 页，禁止 OR | OR 必须改 IN；旧版不能走索引。 | 同列计划常近；跨列看 EXPLAIN。勿背旧口诀。 | `mysql-or-not-must-become-in`；[索引合并](https://dev.mysql.com/doc/refman/8.4/en/index-merge-optimization.html) |
| 约第 104 页，货币小数 | 禁止小数存货币。 | 禁 FLOAT/DOUBLE；用 DECIMAL 或整数分。 | `mysql-money-decimal-not-ban`；[DECIMAL](https://dev.mysql.com/doc/refman/8.4/en/fixed-point-types.html) |
| 约第 116–118 页，MVCC | 行尾两个创建/删除版本列。 | 直觉模型；实现靠 trx id、回滚指针与 undo。 | `mysql-mvcc-not-two-version-columns`；[多版本](https://dev.mysql.com/doc/refman/8.4/en/innodb-multi-versioning.html) |

公开课另补充了秒杀库存不变量、事务性 Outbox 与分布式锁租约三组实践模型。这些是围绕原书主题延伸的教学内容，不宣称原书对应页都存在同样错误。有关资料分别引用 [MySQL 锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)、[Debezium Outbox](https://debezium.io/documentation/reference/stable/transformations/outbox-event-router.html) 与 [Redis 分布式锁](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。
