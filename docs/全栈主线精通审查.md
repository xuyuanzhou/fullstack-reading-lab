## 1. 直接回答

**不能。**

按现在的全栈交付线走完，毕业是 F1 + F2 + F3。这个标准是「能演示一条竖切」，而且 F2、F3 各允许只做一半。八课正文自己写了：读完模型、没有自己实现并制造失败，不等于已掌握。

按架构师主线走到第 3 关，里程碑写的是「能交付的全栈」。第 4～6 关补的是拆不拆、运行和架构职责。授权、跨站提交、契约测试不在任何一关的必读里。第 6 关写明课代替不了那一场决策会。

精通在这里指同一条真实业务做到这些：写对、读对、拒绝不该发生的访问、用测试锁住、一次故障能按层定位、在 CAP 和 Outbox 下说清对用户是成功失败还是等待、用 Docker 和 Kubernetes 把这条路径发布出去并看见故障、留下带反对意见的决策记录。证据是能跑的路径、测试名、一份排查笔记和纪要，不是已读课数。

## 4. 改进：全栈精通线扩成 9 关

毕业改成 F1～F9 都交。旧的 F2「或」、F3「或」取消。架构师关卡 4～6 并进这条线。Outbox、CAP、Docker、Kubernetes 的机制课是必读。排查单独成关，并且放在拆服务之前：本地写路径先能被查清，再谈 Outbox、发布和决策会。

「不要整章塞进」只约束按目录刷完：不把「分布式与高并发」「交付与运行」、JVM、MySQL、前端性能里每一课都设成毕业条件。kubeadm 安装不进默认顺序。Outbox、CAP、Docker、Kubernetes、持续集成与持续交付的机制课，以及关卡 6 点名的排查课，要排进来。

同一笔业务贯穿。每关先交下面的证据，再开下一关。站内 `learningPaths.ts` 已按本节改成 9 关，全栈与架构师共用这一套。

### 关卡 1 · 走通一次下单

必读保持现有 8 课：`fs-four-layers`、`fs-page-feature`、`fs-write-ui`、`fs-frontend-done`、`fs-boot-chain`、`fs-write-invariant`、`fs-read-shape`、`fs-ship-bar`。

**F1：** 四件事各自管什么，外加一条含五种失败的写路径说明。

这一关证明能讲清。它不是精通。

### 关卡 2 · 把写入做对

必读：`spring-transaction`、`mysql-mvcc`、`jpa-optimistic-lock`、`idempotency`、`http-methods`、`spring-mvc-exception`、`schema-migration`。

**F2：** 同一条业务能在本地跑。并发下最后一件库存只有一笔成功，并有一个测试名锁住这件事。同一个幂等键重试不产生第二笔写入。校验失败、业务冲突、未处理错误各自的状态码或 type 是 JSON，不是 HTML。表结构来自带版本的脚本。

写路径一跑就会碰到失败响应和改表，所以异常映射和版本脚本放在这一关，不留到发布。关卡 8 仍要求发布时不在运行中的库上随手改表。Cookie 课在关卡 4。关卡 5 再补契约测试和浏览器路径；这一关的并发测试可以先按「一个测试一种行为」来写，正式读那一课在关卡 5。

### 关卡 3 · 把读取做对

必读：`jpa-session-nplus1`、`sql-keyset-page`、`cache-aside-steps`、`cache-db-double-write-race`。

**F3：** N+1 前后的 SQL 对比，以及写成功后删缓存仍可能读到旧值的那一步。列表说明分页方式。两样都要。

与架构师 D3 对齐，并补上主线正文已经提到、关卡没排的深分页。

### 关卡 4 · 谁能改这一行

必读：`cookie-credential`、`auth-session-vs-jwt`、`csrf-boundary`、`xss`、`spring-security-not-only-login`、`object-level-authz`。

**F4：** 三笔拒绝能演示：未登录、已登录但不是这条资源的拥有者、跨站提交。登录态不放在脚本可读存储里。

这些课已在库里，实施时只改顺序。

### 关卡 5 · 用测试锁住这条路径

必读：`test-one-behavior`、`test-observable-result`、`contract-test-path`、`playwright-user-journey`。

**F5：** 一个不变量测试（名称写清条件和结果；关卡 2 已有的并发测试可以就是这一条）、一条契约测试（失败 type 改名后前端断言失败）、一条浏览器路径（只覆盖用户走完的那一次成功或一种失败）、一条测试证明已登录的用户读不到另一位用户的这条资源。

### 关卡 6 · 一次故障先定位再改

这一关放在拆服务之前。本地这条写路径已经能跑，排查先用在它上面。拆开之后的超时、死信和熔断，仍用这里的顺序。

顺序是：钉住同一次请求，再问慢或错落在哪一层，一次只改有证据的那一层，用同一个指标复测。不把 JVM、MySQL、前端性能整章排进来。

先写一课「排查顺序」（第 5 节，实施时新写），再读已有课：

1. 三份信号各答一题：`otel-three-signals`
2. 日志能对上同一次：`log-correlation-id`
3. 慢落在哪一跳：`request-trace-one-hop`
4. 三只钟不要当成同一个超时：`java-http-timeout`、`nginx-proxy-timeout`、`hikari-pool-timeout`
5. 页面收到的是契约还是 HTML 错误页：关卡 2 已读 `spring-mvc-exception`，这里不再重复，笔记里要能用到
6. 页面慢在等网络、脚本还是布局：`fe-slow-page-where`；只改那一层并复测：`fe-tune-one-layer`
7. 服务慢改最慢那一跳，堆不是总开关：`backend-tune-the-span`
8. 语句按累计耗时找，再看估计行数和实际行数，改完要看到检查行数下降：`mysql-slow-sql-locate`、`mysql-explain-analyze`、`mysql-slow-sql-optimize`
9. 机器先分 CPU、磁盘、内存：`server-slow-which-resource`
10. 内存报错先看名字；暂停对不上接口耗时就先别换回收器；卡住看线程，内存涨看堆：`jvm-oom-signals`、`jvm-gc-choice`、`jvm-thread-vs-heap-dump`

`web-vitals` 作补读。它量的是用户可见等待的分布，不能代替这一次瀑布或链路。

**F6：** 同一条业务的一次故障笔记。写下用户看见什么、数据库留下什么、用来钉住这一次的相关 id 或 trace id、排除了哪一层（证据是哪一张记录）、改了一处之后同一个指标怎么变。笔记里要能指出：这次没查的那一层为什么可以先不动。

### 关卡 7 · 决定拆不拆

并进架构师关卡 4 的全部必读，顺序不变：

`arch-monolith-when`、`arch-modular-boundary`、`arch-scale-before-split`、`arch-soa-classic`、`arch-microservice-split`、`arch-sync-vs-async`、`distributed-one-db-first`、`distributed-saga-is-new-action`、`distributed-cap`、`distributed-consistency-three-words`、`distributed-read-your-writes`、`distributed-outbox`、`distributed-idempotent-key`、`mq-consume-idempotent-key` 与 `message-delivery` 二选一、`mq-dlq-backlog`、`sca-sentinel-java-app`、`sca-sentinel-block`、`circuit-breaker-not-retry`。

`java-http-timeout` 已在关卡 6。这一关用它写清调用超时对用户是哪一种结果，不再重复开课。

CAP 与 Outbox 在这一关，不删、不改成选读。Sentinel 仍只读接入与拦截两课，不把 Spring Cloud Alibaba 整章排进来。

**F7：** 一篇拆或不拆的 ADR；Outbox 或等价方案加上消费幂等，能演示；超时或分区时对用户是成功、失败还是等待；毒药消息进死信，下游持续失败时熔断停止调用。

### 关卡 8 · 上线后能看见故障

并进架构师关卡 5，并补上 Docker 与 Kubernetes 机制课。探针、Deployment、Service 依赖这些课，原来的关卡把它们留在章节里。关卡 6 已读的相关 id、三份信号和「慢在哪一层」这里不再重复列课，交付仍要用那些信号。关卡 2 已读 `schema-migration`，这里不再重复开课。

Docker 必读放在 Kubernetes 之前，按这个顺序：

`docker-what-it-is`、`docker-image-run`、`docker-not-a-vm`、`docker-layer-cache-copy`、`docker-multistage`、`secrets-not-in-image`、`docker-registry-not-just-repo-bucket`、`docker-root-not-host-root`、`compose-service-name-dns`。

持续集成与持续交付放在镜像之后、集群之前。先分清实践和工具，再读工作流怎么拦住失败，最后在认识 Pod 之后读「作业绿了不是线上进程」：

GitHub Actions 是这条流水线的课文，不是 CI 的定义。Jenkins 只读「它是工具之一」那一课，不排 Jenkinsfile 专章。kubeadm 安装仍不进默认顺序。不新写 CI/CD 课。

**F8：** 健康检查（谁接流量、谁重启）；一种延迟或错误率，并写相对 SLO 还剩多少预算；一次压测或故障注入，瓶颈在 CPU、磁盘、内存还是下游（对照关卡 6）；调用方连 Service；发布用的仍是带版本的脚本，密钥不在镜像里。写路径的测试在这次结构变更之后仍然能跑。一条流水线：推送或合并请求会跑测试；测试失败时不构建镜像，也不改正在跑的副本；部署是另一个作业，那一次才会改变副本。

## 9. 关卡进度和选关：浮动，点击才展开

现在路线页把简报铺在地图下面：点一关，读法、课序、交付整块都在。读课时侧栏也一直显示当前关的百分比和下一步。9 关之后这份简报会更长。进度和选关改成浮动，默认只留一枚入口。

地图仍铺开，用来看见人走到哪一座石台。进度百分比、关卡列表、某一关的读法和交付，都放进同一层，不常驻在地图下方，也不占满侧栏。

入口固定在视口一角。折叠时写「第 n 关」、下一节的标题，并带阅读、交付两条短进度。n 是当前进度所在的关。下一节是这一关里还没读的第一节；课已读完、交付未齐时，折叠入口改写「去交这一关」。若人正在看另一关，入口仍显示进度所在的关，面板里再标出正在看的那一关。

点入口展开面板：

1. 先看见关卡列表。每一关一行：名称、已过或进行中、阅读几节、交付几条。
2. 再点某一关，才在这一行下面展开读法、课序和交付勾选。同时只展开一关。
3. 再点这一关的标题，或按 Esc，或点面板外，收起展开的那一关。再点入口，收起整个面板。
