## 1. 还缠在一起的是什么

学员要做的事是：选一道题，写下观察，必要时标出哪一条预期没有成立，然后留下一条待复核记录。

`CurrentTask.tsx` 仍把这件事拆成开始、记下没成立、另记一次、继续这一题、保存、导出、检查导入、三种暂停。开始不产生证据，却挡住未通过记录。保存和记下没成立都会写来源为学员自己的证据。检查导入不写入。换题仍用 `estimatedMinutes` 当主键，一个时长只能有一道题。

首页摘要和卡片内部也不一致：`PathPage` 的摘要优先显示最近一条尝试的题名，卡片打开后仍从 30 分钟题开始。

证据是否待复核、失败后再写一次是否保留旧记录、暂停是否删数据，这些已经在 `learningEvidence.ts` 和 `scripts/learning-platform.test.mjs` 里。下面的子任务不改这些函数。

## 2. 每步都要守住的结果

任何一步做完后，下面几条仍然成立。做不到就停，不进入下一步。

| 编号 | 结果 |

| G1 | 来源是 `self` 的证据读回后 `verification` 仍是 `pending` |
| G2 | 再写一次不删除上一条未通过证据 |
| G3 | 暂停只改 `pause`，不减少尝试和证据 |
| G4 | 继续暂停后打开 `g1.write-path` |

现有用例不用改断言：`a self-report stays pending, and reading does not create a pass`，`a recorded lab failure stays pending, and retry keeps it`，`pause keeps the draft and evidence, and an unknown pause is dropped`。

## 3. 子任务

依赖只按「必须先有」来排。同一文件可以分步提交，但后一步不要提前改前一步的按钮。

```text
T1 一次保存
  -> T2 按任务 id 换题
  -> T3 摘要和卡片打开同一题
T4 离开收成一个菜单     不依赖 T1，但和 T1 都改 CurrentTask，排在 T1 之后
T5 复制记录离开做题路径  依赖 T1 已去掉导入按钮
```

T2 依赖 T1，因为两步都改保存和换题所在的组件，分开写才能各自对照 G1～G8。T4 与 T1 没有数据依赖。T5 要等做题主路径上不再有「检查能否导入」。

### T1 一次保存

范围：只改 `web/src/components/learning/CurrentTask.tsx` 的按钮和点击后的写入。不改 `learningEvidence.ts`。

去掉「记为已开始」「记下没成立」「继续这一题」「保存写下的内容」这四颗里的三颗，收成：

- `保存这一次`：文字为空则不写。没选预期时，尝试状态为 `draft`，证据用 `selfEvidenceForDraft`。选了预期且文字非空时，尝试状态为 `failed`，证据用 `labFailureEvidence`。一次点击只写一次进度。
- `再写一次`：新的尝试 id，草稿清空，旧证据保留。不再先要求状态是 `started`。

已经存在的 `started` 记录仍显示成「这一次还没有记下结果」。保存时按上一段改成 `draft` 或 `failed`。不提升 `schemaVersion`。`hintLevel` 继续写 `0`。

完成：卡片上没有「记为已开始」和「继续这一题」。选一条预期并写下结果后，只按一次保存就得到一条 `failed` 和一条待复核证据。

验收：G1、G2、G6、G8。浏览器打开 30 分钟题，保存前后数 `revision`，只增加 1。

### T2 按任务 id 换题

范围：`CurrentTask` 的换题状态。数据仍在 `learningTasks.ts`，不新增题。

`useState` 存任务 `id`，不再存 `estimatedMinutes`。分钟留在按钮上当说明。查找用 `id`。同一分钟以后可以有第二道题，这一步不添加那道题。

完成：换题按钮的 `aria-pressed` 跟任务 id 走。15、30、60 分钟三道现有题仍都能打开，命令和参考答案跟着题走。

验收：G6、G8。浏览器从 30 分钟换到 15 分钟，没有本机命令；再换到 60 分钟，有三条预期。

### T3 摘要和卡片打开同一题

范围：抽出一个纯函数，供 `PathPage` 摘要和 `CurrentTask` 初始题共用。建议放在 `web/src/data/learningTasks.ts` 旁边的小函数，或 `learningTasks.ts` 内：给定尝试列表，返回要打开的任务 id。有未删除的最近尝试就用它的 `taskId`，否则用 `g1.write-path`。

这一步改默认题。现在卡片默认 30 分钟，摘要却可能是另一题。收成「没有尝试时用 15 分钟那题」。这和 G4 的继续目标一致。

完成：合上的摘要题名与展开后的题名相同。没有尝试时两边都是「写下这一笔订单的四段职责」。

验收：G4、G8。浏览器在无尝试和有一条 `g2.concurrency-note` 尝试两种记录下各看一次摘要和展开后的标题。

### T4 离开收成一个菜单

范围：`CurrentTask` 里三颗暂停按钮。

保留一天、一周、一个月三个取值，因为 `PauseChoice` 已是这个联合类型。界面收成「先离开」下面的一个选择，不再和保存并列成三颗主按钮。继续仍清除 `pause` 并打开 `g1.write-path`。

完成：主路径只剩保存和再写一次。离开后的 `pause.choice` 仍是 `day`、`week` 或 `month` 之一。

验收：G3、G4、G8。

### T5 复制记录离开做题路径

范围：从当次任务卡片去掉「检查能否导入」。导出改成一颗「复制记录」，仍调用 `exportEnvelope`，文本出现在卡片下方，不另存文件。

`previewImport` 函数留在 `learningEvidence.ts`。这一步不在卡片上做导入预览，也不做确认写入。确认写入若以后要做，是记录恢复的另一步，不放回这张卡片。

完成：做题时看不到导入。复制之后文本能被现有 `previewImport` 解析，且这个动作不增加证据。

验收：G1、G5、G8。浏览器复制一次，证据条数不变。

## 4. 不做的流程

| 现有动作 | 处理 |
| --- | --- |
| 记为已开始 | T1 删除。它不产生证据 |
| 继续这一题 | T1 删除。再写一次已经留下未通过记录 |
| 记下没成立与保存各写一次 | T1 合并成保存这一次 |
| 检查能否导入 | T5 移出卡片。它不写入 |
| 用分钟当任务主键 | T2 改为任务 id |
| 摘要和卡片各选一题 | T3 共用一个函数 |
| 三种暂停与保存并列 | T4 收进先离开 |
| 在线跑 Maven、把自述改成已通过、提升 schemaVersion | 不做 |

首页的懒加载和补强标签已完成，不纳入这五步。见 [架构师主线首页把做题和补强收出首屏](./ai-changes/2026-10-13-path-home-length.md)。

## 5. 怎样分步落地

每步只改该步点名的文件，做完跑第 2 节的 G8，并做该步自己的浏览器核对。五步都做完后，再按简化方案第 6 节的 F1～F10 走一遍。F1～F10 不是每步的门槛，避免一步里同时改保存、换题和暂停。

建议顺序：T1、T2、T3、T4、T5。T4 可以插在 T1 之后的任意位置。不要并行改 `CurrentTask.tsx`。

一步失败时只回退该步。存储函数和测试断言保持不动，回退不涉及数据迁移。
