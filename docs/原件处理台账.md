# 原件处理台账

“全部搞定”按五层状态管理，避免把“文件能打开”误当成“知识已经核验”：

1. **已解析**：原件或压缩包成员已进入本机索引；无可靠文字的图片另行人工处理。
2. **已定位主题**：从原件结构中提取可学习的课程主题和位置。
3. **已有草稿**：课程已独立改写，明确标记待核验，不进入网站。
4. **已核验**：核心结论已对照官方资料、标准、固定版本源码或可复现实验修订。
5. **已发布**：课程通过结构检查并进入公开站点。

本机当前有 3,210 个阅读条目：前端 1,659 个，Java 1,551 个（含 4 份 CHM）；3,077 个已有可用文字，133 个仍无文字（123 张图片、10 个文档或文本）。`source_progress.py` 会为每个条目保存课程状态和核验状态，私人路径与备注位于被 Git 忽略的数据库中；公开仓库只记录这些汇总和处理规则。

每批流程为：前端与 Java 分线选取原件 → 提取说法并标记 → 批量产生待核验草稿 → 按风险集中核验 → 修订发布 → 回写台账。一个原件即使有课程草稿，也不会自动标成“已核验”；只有完成依据记录后才能进入公开课程统计。

正在处理的两份 PDF 已完成说法级核验（「已有草稿 / 已核验」）。说法清单写在 [核对交接](核对交接.md) 与 [核对队列](核对队列.md)。文件级备注在本机数据库，不进入公开站点。

```bash
python3 source_progress.py --sync --summary
```
