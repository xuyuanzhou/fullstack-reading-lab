## 1. 直接回答你的问题

**按侧栏顺序学完，能不能成为高级架构师？**

**不能。**

| | 本课库按顺序学完 | 高级架构师 |
| --- | --- | --- |
| 产出 | 机制正确、能排错、能过技术深挖 | 在约束下划边界、做取舍、让多团队长期可演进 |
| 证据 | 课打卡、口述、单功能正确 | 架构决策落地、质量属性达标、事故与演进可追溯 |
| 缺什么 | —— | 组织约束、容量与成本、跨系统演进、评审与推动 |

本库是 **架构师的「零件与错念」教材**，不是架构师学位。  
「按顺序学完」只会把你练成 **知识面很宽的高级开发 / 技术专家候选人**；架构师要另走一条更短、更硬的主线。

下面这套设计：**一条顺序、六个关卡、每关一个交付物**。过关靠交付物，不靠课数。

## 2. 重新设计的学习顺序（只这一条）

不要前端整轨 + Java 整轨刷完。只走：

```text
关卡 1  单笔业务竖切（全栈主线）
   ↓
关卡 2  正确性：事务 / 幂等 / 失败语义
   ↓
关卡 3  性能与副本：库 · 缓存 · 查询
   ↓
关卡 4  分布：消息 · 一致性语义 · 何时不拆
   ↓
关卡 5  运行：发布 · 观测 · 失败产品语义
   ↓
关卡 6  架构职责任务（课库外，强制）
```

每关 **先交付，再往下**。没交付就停，不要开下一关的课。

## 3. 六关细则

### 关卡 1 · 单笔业务竖切（约 1～2 周）

**必读（按序，仅此 8 课）：**

1. `fs-four-layers`
2. `fs-page-feature`
3. `fs-write-ui`
4. `fs-frontend-done`
5. `fs-boot-chain`
6. `fs-write-invariant`
7. `fs-read-shape`
8. `fs-ship-bar`

**交付物 D1：** 写清页面、接口契约、用例、持久化各守什么，外加一条真实或仿真业务的成功路径说明。  
**过关标准：** 不看资料能讲清：按钮态、契约 type、事务、唯一约束各管什么。

---

### 关卡 2 · 正确性（约 2～3 周）

**必读（按序）：**

1. `spring-transaction`
2. `mysql-mvcc`（两次普通查询都能看见同一库存；先查再改守不住）
3. `jpa-optimistic-lock`（后提交的旧版本必须失败）
4. `idempotency`
5. `http-methods`（幂等与 HTTP 语义）
6. `cookie-credential`（或你栈里的会话边界 1 课）

**交付物 D2：** 可运行的写路径，含：对照 MVCC 与 `@Version` 的并发不变量测试、幂等重试不双写、失败类型表。  
**过关标准：** 「200」和「不变量已提交」不会再说成同一件事。

---

### 关卡 3 · 读、库、缓存（约 2～3 周）

**必读（按序）：**

1. `jpa-session-nplus1`（或同主题 1 课）
2. `cache-aside-steps`（旁路：读回填、写时删）
3. `cache-db-double-write-race`（写成功后删缓存仍可能读到旧值的那一步）

穿透/热点或索引约束 **最多再 2 课**（按缺口，例如 `cache-penetration-vs-breakdown`），不进默认顺序。

**交付物 D3：** 读路径 + 缓存失效；N+1 前后对比；一次「读到旧数据」复盘。  
**过关标准：** 能画「写成功 → 缓存 → 再读」时序，并标出唯一可能脏的一步。

---

### 关卡 4 · 分布与边界（约 3～4 周）——架构师分水岭

**必读（按序）：**

1. `arch-monolith-when`
2. `arch-modular-boundary`
3. `arch-scale-before-split`
4. `arch-soa-classic`（远程服务化常停在共享库与中心总线；不等于微服务）
5. `arch-microservice-split`
6. `arch-sync-vs-async`
7. `distributed-one-db-first`
8. `distributed-saga-is-new-action`（补偿是一笔新业务）
9. `distributed-cap`
10. `distributed-consistency-three-words`
11. `distributed-read-your-writes`（写成功的下一次读可能还看不到）
12. `java-http-timeout`（建连超时管不到整次调用）
13. `distributed-outbox`
14. `distributed-idempotent-key`
15. `mq-consume-idempotent-key` 或 `message-delivery`
16. `mq-dlq-backlog`（毒药消息进死信，积压要能看见）
17. `sca-sentinel-java-app`（Java 应用接入）
18. `sca-sentinel-block`（限流拦截语义；不啃整章 SCA）
19. `circuit-breaker-not-retry`（熔断是停止打下游，不是更勤的重试）

**交付物 D4：**

- 一篇 **ADR**：这个业务「拆 / 不拆」的决定与放弃方案  
- Outbox（或等价）+ 消费幂等可演示  
- 回答题：分区或超时时，对用户是成功、失败还是等待？写后读和调用超时各是哪一种。  
- 失败处理：毒药消息进死信；下游持续失败时熔断停止调用，重试另有预算。

**过关标准：** 不会把「上了微服务」写成架构能力；能说出分布式成本与收益。

---

### 关卡 5 · 运行与演进（约 2～3 周）

**必读（按序，与 D5 对齐）：**

1. `k8s-probes`（健康检查 / 探活）
2. `otel-three-signals`（延迟、错误率等指标与链路）
3. `log-correlation-id`（同一条请求的日志对得上这一次故障）
4. `server-slow-which-resource`（压测或故障注入后瓶颈在哪一层）
5. `spring-graceful-shutdown`（发布不停机截断）
6. `k8s-deploy-not-lone-pod`（发布形态）
7. `k8s-service-clusterip`（调用方连 Service，不写死 Pod IP）
8. `schema-migration`（表结构跟版本走）
9. `arch-slo-budget`（错误预算：这次还能不能发）
10. 补读：`arch-evolution-stages`、`arch-split-order-case`（把架构图接到发布与观测；两课都读，不是二选一）

侧栏交付与运行、工程实践仍可按缺口再补，不必整章刷完。

**交付物 D5：** 健康检查 + 至少一种黄金指标（延迟或错误率，并写相对 SLO 还剩多少预算）+ 一次压测/故障注入结论（瓶颈在哪一层）+ 发布说明（调用方连 Service；表结构用带版本的脚本）。  
**过关标准：** 架构图能对应到「怎么发布、怎么看见坏了」。

---

### 关卡 6 · 架构职责任务（约 3～4 周，课外为主）

**必读（按序）：**

1. `arch-design-one-path`（一条路径的容量、数据归属、失败时用户看见什么）
2. `arch-cost-tradeoff`（成本与延迟、失败写在同一页）
3. `arch-contract-review`（消费方在场的契约评审）
4. `arch-evolution-roadmap`（3～6 个月只做一件事）

SLO 用关卡 5 的 `arch-slo-budget`，不在本关重复。决策会没有课，必须在工作或等价场景完成：

| 任务 | 交付物 |
| --- | --- |
| 质量属性 | SLO / 容量粗算 / 成本任一页纸 |
| 跨团队契约 | 一份接口或事件契约评审纪要（你主导） |
| 演进 | 现存系统的「下一步只做一件事」路线图（3～6 个月） |
| 推动 | 一次架构评审或技术决策会，有结论与反对意见记录 |

**过关标准：** 别人能按你的 ADR 和路线图干活，而不是只听你讲中间件名词。

**全部六关过完 → 才具备「高级架构师」答辩材料。**  
只刷到关卡 5、缺关卡 6 → 仍是资深个人贡献者，不是架构师。

## 4. 课库要怎么改（产品设计，避免再乱）

### 现在的问题

1. 侧栏「按章顺序」暗示学完即闭环 → **误导**  
2. 前端轨 / Java 轨平行过长 → 架构能力被淹没  
3. 缺「架构师关卡」入口与过关物 → 用户只能自己拼 90 天表，越拼越乱  

### 优化原则（采纳）

| 原则 | 做法 |
| --- | --- |
| 一条主线 | 站内增加「架构师主线」入口，顺序 = 上文六关，而不是 23 个 Java 章 |
| 索引其余 | 语言 / 框架 / 微前端 / 全量 SCA = 工具书，默认折叠 |
| 关卡墙 | 进度以 D1～D6 勾选为准，不用「已读课数 %」当架构进度 |
| 诚实文案 | 首页/主线说明写清：学完公开课 ≠ 架构师；关卡 6 在课外 |
| 少而硬 | 点名必读 **49** 课（消息二选一按 1 计）。关卡 5 演进两课为补读，另计。禁止把 700 课线性化 |

### 建议落地（工程，可分步）

1. **P0（文档，已做）**：本文作为唯一权威路径；旧「90 天 / 10 年勾选」降级为附录入口  
2. **P1（产品，已做）**：`/#/paths/architect`、`/#/paths/fullstack`，侧栏「交付 / 架构 / 索引」。进度勾选（F/D 手写清单）仍未做  
3. **P2（内容）**：每关末尾加一页「关卡验收」课（task = 交付物，无新知识点）  
4. **P3（内容缺口）**：质量属性、一条路径、成本取舍、契约评审、路线图写法已有课并挂进主线。决策会仍无课，在工作里完成。  

未做 P1 前：你只用本文 + 课 id 手动走，不要再并行多份计划。
