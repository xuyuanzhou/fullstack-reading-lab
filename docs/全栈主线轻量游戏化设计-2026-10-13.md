## 2. 一次学习的最小循环

```text
打开 -> 继续上次 / 选可用时间
     -> 看一个小目标和完成条件
     -> 阅读或尝试
     -> 获得具体反馈
     -> 保存证据或草稿
     -> 休息 / 下一小步
```

默认只突出当前任务、一个下一步和可选提示；整关知识树、全部交付物、成就列表折叠为次级入口。不得把 31 节课程和全部验收条件同时作为首页任务。

| 时间档 | 任务类型 | 示例 | 结束条件 |
| --- | --- | --- | --- |
| 15 分钟 | 回忆/阅读/预测 | 画出两次并发扣库存的时序 | 有一份草稿和一个待验证问题 |
| 30 分钟 | 小实验/修复 | 写出条件更新与一条失败测试 | 测试运行过，失败或成功都记录 |
| 60 分钟 | 项目增量/验证 | 接入幂等约束并跑并发回归 | 对照验收保留证据；没完成可存断点 |

时长是预估，不是倒计时；学员可改用时预算。超过预估显示“保存到这里，下次继续”，不显示逾期或失败。

### G2 的任务拆分示例

1. 15 分钟：用两条请求解释不变量和潜在竞态。
2. 30 分钟：实现条件更新，先用一条错误实现证明测试会失败。
3. 30 分钟：加唯一键与同键异参检查。
4. 30 分钟：模拟提交后响应丢失，原键重试。
5. 15 分钟：写下实验结果和尚未验证的边界。
6. 可分天进行的关卡验收：笔试、完整回归、20 分钟答辩。

这些只是 G2 中一个任务包，不暗示两小时能学完事务、隔离级别与全部并发知识。正式关卡时数见总方案。

## 3. 关卡与挑战解锁

“解锁”只控制推荐挑战和验收准备状态，不锁课程全文或历史记录。先修不足仍可预览并自行尝试练习，系统只停止推荐正式验收，不禁止探索。

| 对象 | 状态 | 条件与显示 |
| --- | --- | --- |
| 课程 | 未读 / 已读 / 待复习 | 任何时候可打开；已读只算阅读 |
| 挑战 | 先修待补 / 可尝试 / 进行中 / 待复核 / 已验证 | 满足先修或免修证据才推荐正式验收；任何人都能预览并自行练习，先修不足不生成正式通过结论 |
| 关卡 | 待准备 / 可开始 / 学习中 / 待验收 / 已通过 | “已通过”仅在必需任务和该关考核均满足下表规定的验证条件时显示；自评进度与旧版勾选另列 |
| 能力 | 0～4 与证据来源 | 阅读、自评、自动行为检查、同伴评审分开标注 |

依赖规则：

- 使用能力和稳定任务 id 的有向无环图，不按文案解析“二选一”。
- `allOf` 表示全部满足，`anyOf` 表示替代方案；R/V 两框架要求用 `allOf`，MQ 工具选项可用 `anyOf`。
- 能浏览 G7 并不表示已掌握 G2；缺先修时列出最多三个直接依赖和一个补齐入口。
- 免修走同等证据检查，不因点击“我会”就标已验证；自评也可继续阅读和实验。
- 学员不愿上传证据时可本地记录自评，不阻碍学习；显示“自评完成”，不能显示外部认证。
- 必修题失败仅回到该任务“进行中”，不回收前关通行权、不让整条地图变灰。
- 可选内容后来转必修，要新版本和说明；旧关卡保留“按旧版自评完成”，只新增待补项。

### 3.1 证据来源与“通过”判定

首版是静态站，没有受信任的在线代码运行和身份服务。“已验证”只能指**本站可重跑的限定检查**或**已记录的人工评审**，均须标来源和范围；不能宣称第三方认证、防作弊或完整能力证明。保存文本、填写“测试通过”、粘贴日志与导入文件都只是学员提供的材料，不能凭自身内容升级为自动验证。

| 来源 | 界面显示 | 可用于什么 | 不能直接证明什么 |
| --- | --- | --- | --- |
| 阅读、旧版 `pathChecks`、手动登记的本地命令/测试日志 | 已读 / 自评完成 / 待复核 | 保留练习与证据线索，继续下一小步 | 代码实际通过测试、笔试或口述已由他人验证 |
| 本站对受控输入可重跑的判断题或本地确定性检查 | 本地检查通过（附题版本、用例范围） | 满足该题**明确声明**的自动检查项 | 外部实验的真实执行、全部边界或生产能力 |
| 经人实际审阅的实操、设计或口述 | 本地登记的人工评审通过（注明评审方式与责任人） | 满足对应人工评审项；若只是学员自行登记，则保持待复核 | 本地网页可以核实评审人身份或防止记录被修改 |
| 未运行、无评审人、检查失败或异步结果未返回 | 未运行 / 待复核 / 检查未通过 | 呈现下一步、允许保存和重试 | “已通过”“已验证”或相应验证成就 |

每项必修考核在任务元数据里声明 `acceptedEvidence` 与 `requiredReview`：能由站内受控检查判断的笔试项可在检查通过后标“本地检查通过”；外部 Java/React/Vue 实操先标“自评完成，待复核”，口述和设计须有人审。关卡“已通过”仅在全部必修项满足各自规则后展示，同时带上“本地检查/人工评审”的来源；没有评审人时保持“待验收”，但课程、后续关卡练习和个人自评不受阻。能力 3～4 级与 G1/G2/G6/G8/G9 的验证成就也必须满足其规定的评审条件，不能从勾选或自行上传日志推算。

人工评审在首版没有可信身份验证：实际参与评审的人查看材料并在本机登记结论时，可以显示“本地登记的人工评审通过”，但不能叫平台认证；仅由学员自行填写“已有评审”的记录仍待复核。没有评审人时不强制找人才能继续学习，但不能获得对应关卡的本地评审通过状态。未来启用身份化评审时另定数据迁移与信任等级，不能自动升级旧记录。

### 3.2 旧用户与新版状态共存

旧版 `gateCleared` 用已读和 `pathChecks` 显示“已过”；迁移时冻结其输出顺序和版本，给原判定留下历史快照。旧勾选导入自评，不导入验证证据。新版地图同时区分三件事：

| 旧版记录 | 新版显示 | 下一步 |
| --- | --- | --- |
| 旧判定已过，但没有新版考核证据 | 按旧版自评完成；新版待验收 | 保留原阅读与交付勾选，展示缺少的新版考核；不显示新版“已通过” |
| 旧判定未过，但完成部分阅读/交付 | 学习中（显示已读与自评数量） | 从未完成的小任务继续；不要求重复读已读课 |
| 旧判定已过，且后续新版证据达标 | 新版已通过，附原自评历史 | 已验证项目不重新计数，旧数据仍可查 |
| 新版本把选修改为必修 | 按旧版自评完成 + 新版待补项 | 旧成果不撤销；待补项不自动变成失败或已验证 |

地图默认推荐按**新版尚缺的证据**定位，允许用户一键回到上次看的关；提示“原有进度已保留，新版验收需要补充证据”。不要把历史自评改名为当前证书，也不要把所有旧关卡统一显示为“未学习”。变更初次出现时说明新旧口径和每关差异，可关闭提示但保留说明入口。

## 4. 成就、挑战与反馈

成就采用固定事实，不设随机掉落、连续签到损失或公开竞争。

| 成就展示名 | 触发规则 | 不代表 |
| --- | --- | --- |
| 完成第一次尝试 | 保存首份任务草稿或执行结果 | 不代表实现正确 |
| 完成一条业务 | G1 行为验收通过 | 不代表可上线 |
| 守住并发不变量 | G2 并发与幂等任务证据通过 | 不代表所有并发问题已掌握 |
| 完成双框架验证 | React 与 Vue 各自的实现、机制、测试、性能任务通过 | 不能只完成其中一个就发放 |
| 定位一次故障 | G6 排障记录通过证据检查 | 不能只写“重启好了” |
| 完成恢复演练 | G8 真正恢复与完整性检查通过 | 有备份文件不够 |
| 完成设计答辩 | G9 评审与口述达标 | 不授予架构师职称 |

同一任务版本只触发一次成就；重复阅读、刷新页面、重新导入相同记录不能刷次数。默认没有经验值；未来增加积分也不能替代能力验收。

挑战分“基础练习”和“迁移挑战”。基础练习覆盖必修行为，迁移挑战改变一个约束，例如从单用户改双租户、从成功请求改丢响应。日常只推荐一个，学员可以关闭推荐。

即时反馈分层：

1. 操作反馈立即给出：已保存/未保存、已开始/已暂停。
2. 判断题立即显示预期要点及一个反例，不用红色羞辱文案。
3. 代码任务的检查失败展示实际/预期与相关测试名；只验证测试能证明的行为。
4. 复杂设计题显示评分维度、缺失证据和人工复核状态，不制造“秒判系统设计”。
5. 一次只建议一个优先补点；参考答案、下一层提示由学员主动展开。

## 5. 进度可视化与低压力机制

进度不合成一个误导性的“精通百分比”。首页展示当前小任务、关卡完成数；展开后分别查看：

- 阅读：已读必需学习单元 / 必需学习单元，替代组只计一次。
- 实践：已按任务声明的来源完成验证的必需任务 / 必需任务；另显示自评完成与待复核数。标清本地检查、人工评审登记和未验证，避免把这些合成外部认证。
- 能力：按 Java、React、Vue、数据、分布式、排障等领域列等级与最近证据日期。
- 选修：单独展示，不增加必修分母；无必需任务时显示“不适用”，不伪造 100%。

暂停一天、一周或一个月不扣任何记录。返回时提供最近证据、未完成的具体步骤及一个 15 分钟复习入口；不补发积压通知，不要求补签。

反馈文案示例：“并发测试还有一项未通过。表单和接口测试已保留，下一步检查唯一约束。”不得写“你失败了，退回第二关”。

所有奖励与动效可关闭；不自动播放音效。不使用高强度闪烁；遵从 `prefers-reduced-motion`。键盘焦点、触控点击区域、对比度和屏幕阅读器的状态信息必须可用。

## 6. 数据与兼容性规格

以下为待实现的数据合同，不是当前代码已存在字段。

| 实体 | 必需字段 | 约束 |
| --- | --- | --- |
| 学习单元 | id、lessonIds、requirement、alternativeGroupId、skillIds | requirement 明确必需/可选；id 不依赖数组下标 |
| 任务 | id、version、gateId、skillIds、prerequisites、estimatedMinutes、required、rubric、acceptedEvidence、requiredReview | 声明可检查的行为和必须由人审的项；删除或修改评分要求必须版本化 |
| 尝试 | id、taskId、taskVersion、status、startedAt、savedAt、hintLevel、draft | 同一任务可多次尝试；draft 只存小段非敏感草稿，大型附件不放浏览器记录 |
| 证据 | id、attemptId、kind、reference、summary、verification、source、taskVersion；有检查或评审时再填 checkedAt、reviewerKind | 来源区分自报、本站检查和人工评审登记；记录检查范围/结果，未运行不等于通过；本地路径不假装云附件 |
| 能力记录 | skillId、level、evidenceIds、assessedAt、assessmentKind | 等级依据显式评审，不能由阅读数推导 |
| 成就 | achievementId、ruleVersion、evidenceIds、earnedAt | 唯一键防重复，内容升级不静默伪造新证据 |
| 存储信封 | schemaVersion、revision、records、updatedAt | schemaVersion 与并发 revision 含义分开；写入成功才更新“已保存”状态 |

旧数据迁移：

1. 保留 `done`、笔记、近期记录和 `pathChecks` 原数据，迁移前可恢复备份。
2. 旧 `pathChecks` 是 `${gateId}:${index}`，必须使用迁移时冻结的“旧索引 -> 稳定交付物 id”映射；禁止调换 `outputs` 后直接复用索引含义。
3. 旧勾选只导入“自评完成”，不自动生成测试报告、等级 3 或双框架成就。
4. 显式补读分类上线后重新算阅读分母，但保留已读事实；说明口径变更，不删除课程历史。
5. 多标签页用任务/证据记录 id 合并；撤销需要删除标记或等价策略。不能照搬旧数组取并集，让取消勾选被另一标签页复活。
6. 非法/过旧/未来 schemaVersion、配额或隐私模式失败均可降级阅读；未知字段不能导致整份记录丢失。导入前校验和预览，不盲信 JSON。
7. 可导出经过版本标记的记录，再导入恢复；新增跨设备同步需另行设计身份、冲突与隐私，本期不假装本地存储已跨设备。

### 6.1 跨标签撤销与旧版共存

新记录不能直接沿用 `progressStorage.ts` 中对 `done/pathChecks` 取并集的策略；那会让另一标签页的旧值把撤销复活。P2 实现前先固定存储后端与版本边界：推荐用 IndexedDB（浏览器内可跨标签事务读写的数据库）保存新增的尝试、证据、自评与撤销操作，同一条记录的读取、版本核对和写入放在一次 `readwrite` 事务中。现有 `localStorage` 记录只作为迁移来源与可恢复的只读历史；不要让 v1 与 v2 同时把同一字段当主真相源。改用另一存储后端必须证明同等的原子读写与跨标签冲突测试，否则不得承诺“不静默恢复撤销”。

| 场景 | 规则与用户可见结果 |
| --- | --- |
| 两标签修改不同记录 | 按稳定记录 id 合并；两个改动都留存 |
| 标签 A 撤销记录，标签 B 基于旧版本保存同一记录 | 记录撤销标记和变更版本；B 的旧写入不得覆盖撤销，提示“这项已在另一标签更改，请确认是否重新提交” |
| 两标签基于同一版本修改同一条草稿 | 不按最后写入时间静默覆盖；保留冲突副本或可导出版本，提示选用哪一份 |
| 撤销后用户看见最新状态并明确重新提交 | 新操作有新 id/版本；可以重建该项，不能复活已撤销的旧证据 |
| 导入旧备份 | 先预览并去重；旧自评不能覆盖新版撤销或生成验证结论；有同项冲突须用户确认 |
| 旧版页面仍在另一标签写 `localStorage` | v2 不自动把新增的 v1 勾选合并成新版验证；提示旧标签可能未保存到新版，请关闭旧页后预览导入差异 |

删除标记至少保留到可确认所有活动标签已应用该操作；静态站没有跨设备确认机制，本期不自动清理新记录的删除标记。不要用墙上时钟的 `updatedAt` 判定不同标签谁赢；冲突比较基于事务内的记录版本与操作 id。迁移完成后冻结旧 `gateId:index` 映射并留下旧数据恢复入口；新流程不得继续根据旧数组位置计算通过。

### 6.2 写入失败、导出与恢复

新增数据写入失败（配额、权限、浏览器隐私限制或事务异常）时，保留当前页**内存中的最新尝试**，显式提示“未保存到本机”，停止显示已保存/跨标签同步成功；绝不从刚失败的持久层重新读取旧快照当作最新导出。提供从内存构造的版本化、脱敏 JSON 下载；浏览器不支持下载时显示可选择复制的小段内容和明确的未保存警告。不能保证内存可跨刷新或关闭保留，刷新/离开前提示先导出，关闭后无备份则如实说明无法恢复。

导出成功只证明文件已由浏览器创建，不证明用户已安全保管；导入先展示 schema、记录数、冲突项和来源，再确认合并。若导出/下载也失败，不显示“已备份”，保留页面中的可复制内容并告知风险。旧存储损坏时只读旧备份与本次内存状态分别展示，不以空对象覆盖唯一可恢复的原文。试学需实测：存储写失败后编辑草稿 -> 导出仍含最新编辑 -> 刷新警告 -> 导入恢复；下载失败与无备份退出另测。

## 7. 代码执行与隐私边界

MVP（最小可用版本）只提供本地运行命令、测试结果登记和人工评分；浏览器不在应用主域 `eval` 学员代码。外部实验的命令和日志是自报证据，没有后端执行环境时显示“未由本站运行，待复核”，不能把提交文本当测试通过。站内受控判断题仅标本地检查通过，不扩展为外部代码实操通过。

后续在线判分是独立工程：隔离容器/进程、禁网默认、资源/时长限制、无生产凭证、滥用防护、队列与审计。安全验收前不开放；不能把学习网站的部署权限交给任意题目脚本。

学习分析默认本地或明确选择加入，只采任务类型/版本与聚合结果；不上传源码、个人笔记、公司代码或转储。用户可导出、删除记录。AI 辅助评分需提示数据去向，默认不用真实企业材料。

## 8. 实现顺序与验收

每个批次独立验收，不先搭庞大的积分和社交系统。

| 批次 | 涉及位置 | 验收标准 |
| --- | --- | --- |
| 1 显式元数据 | `learningPaths.ts`、`masteryGates.ts`、新增任务数据 | 课程 id 有效、任务 id 唯一、依赖无环；必需/补读/替代组计数正确；空组拒绝配置 |
| 2 记录兼容 | `progressStorage.ts`、`progress.tsx`、新增记录存储与类型定义 | 冻结旧映射；旧数据/旧版标签、自评、写入与下载失败、损坏数据、导入预览、同项冲突与撤销均有单测 |
| 3 最小学习循环 | `GateDock.tsx`、`PathPage.tsx` | 能选时间、只突出一个任务、保存断点、看到下一步；课程始终可自由阅读 |
| 4 挑战与反馈 | 任务详情、证据与评分组件 | 自报/本站检查/人工评审登记来源分开；无人评审保持待复核，可继续练习；异步未完成不判通过 |
| 5 成就与进度 | 地图、能力列表、成就摘要 | 不重复授予，React/Vue 全部条件才发双框架成就；旧版自评完成与新版已通过分开 |
| 6 可访问性与试学 | 浏览器测试与用户试用 | 键盘、读屏状态、移动端、减少动效；反馈用时/卡点，再校准任务长度 |

至少覆盖下列场景：

1. 新用户首次打开：不出现强制答题墙，能开始预备小任务。
2. 老用户已读所有课程：保留阅读；无证据仍标自评，不自动通过能力验收。
3. G2 一题失败：其他证据保留，可以阅读 G3，G3 推荐挑战说明缺少的先修。
4. 学完替代组一课：另一课不影响阅读分母；选修未读不拦住关卡。
5. 完成 React 但未完成 Vue：双框架能力仍不满足，成就不发。
6. 暂停后返回：草稿、进度、最近任务完整；不显示断签惩罚。
7. 重复提交/刷新/导入：证据与成就不会翻倍。
8. 多标签页一边撤销、一边保存同一记录：撤销保留并提示冲突；另测不同记录并发编辑、旧版标签和明确重新提交。
9. 存储失败：提示“未保存”，内存最新草稿可导出且不会被旧快照覆盖；导出也失败时保留可复制内容并提示刷新风险。
10. 任务版本更新：旧版成绩有标记，新要求单列；不追溯取消旧成就。
11. 键盘完成主流程，屏幕阅读器能获知保存结果；仅颜色不能表达失败。
12. 未配置判分服务或无人评审：外部实操显示待复核，站内可重跑题标本地检查来源；练习可继续，关卡不伪造通过。
13. 旧用户已自评通过多关：地图保留“按旧版自评完成”历史，新版待验收项目逐关列出，不一键清零或冒充验证。

## 9. 衡量是否真的更轻松

先做 5～8 名不同基础学习者的可用性试学；样本只用于找问题，不作统计上的学习效果证明。记录首次找到任务耗时、能否独立恢复、错误反馈可理解性、每项任务实际用时和主观负担。

核心目标是“能开始、知道下一步、愿意回来、会得更扎实”。观察延迟复测表现与证据质量，不能只看访问时长、打卡天数或成就数量。若任务完成率高但变体题仍不会，应改教学与反馈，而不是加奖励。
