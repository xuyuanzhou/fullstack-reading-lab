## 背景

用户要求在完整培养与游戏化方案之上补齐项目实施流程，具体到阶段目标、任务、排期、资源、风险、交付和验收；同时要求覆盖 Grok 4.7 与 TRAE 内置模型，便于更换模型继续落地。

## 决策

- 采用：P0～P8 九个建设阶段，20 周、1280 任务人时加 320 缓冲人时；前提为每周 80 合计人时的人员配置，不是学员学习周期或单人承诺。
- 采用：学习站沿用 React 静态部署，Java/Vue/分布式等作为独立教学实验；本期不顺带搭建在线判题 SaaS。
- 采用：核对官方模型目录及开发文档，覆盖 19 个 TRAE 内置型号与额外 Grok 4.7；可用性取决于用户账号、地区、套餐和工具接入。
- 采用：Astra 用于高影响推理/复核、Sol 用于常规实现、Grok 4.7 用于高阶实验和异源复核、Gemini Pro 用于多模态复核、Luna 用于低成本初筛；均为项目试测前的初始推荐。
- 采用：其他候选逐项列出价格、建议位置和待试测限制，不因型号名称或价格虚构技术能力排名。
- 不采用：不声称全型号实测最优，不自动配置密钥、购买额度、调用其他模型或启动子代理。
- 不采用：不运行会更新课程导出的构建，不修改已有网站/课程/进度代码，不覆盖其他会话未提交改动。

## 给下一模型

1. 先读本文及索引最近记录，再读实施总计划和模型交接；原培养路线仍决定要教什么。
2. 一次只接一个 4～16 人时任务卡，明确允许文件、验收、工具与停止条件。
3. 新建路径和测试命令在方案中均是待实施建议；先确认目录和 package 脚本，不假装已经存在。
4. `npm --prefix web run check` 会导出并构建，需在隔离工作区或归属明确后运行；新测试文件还要接入真实测试命令。
5. 模型推荐有官方定位与价格依据，但没有本仓库跨模型跑分；不要把“待试测”删成“已证明最优”。
6. Git、云费用、密钥和生产操作仍需用户授权，模型不能自授权限。
