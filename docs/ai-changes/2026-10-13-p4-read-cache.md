## 背景

查询与缓存要能在真实数据库上重复看到：排序值重复时下一页会漏行，以及写库删缓存之后旧值仍可能被放回缓存。

## 决策

- 采用：`labs/order-g3` 使用 MySQL 8.4。五条合成订单里有两组相同的 `created_at`。下一页条件是 `(created_at, id)`，索引是 `idx_sale_created_id`。只比较创建时间的查询会漏掉同一时间的 `id` 4。按订单逐条查商品名比一次连接多 5 次语句。详情缓存允许状态短暂旧于数据库；测试在读取和放入之间把数据库改成 `paid` 并删键，缓存里仍是 `new`。顺序用闩锁固定，不用 `sleep`。
- 不采用 / 刻意不做：不把库存放进这个缓存。不写 React 或 Vue 的请求竞态。不删掉回填测试来假装窗口不存在。不勾选 P4-02。不把结果写进路线页勾选。不提交，不发布。
