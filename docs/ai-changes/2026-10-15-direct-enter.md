## 背景

一关里面，阅读和交付都应该是同一套闯关：细进度条加上石台。点一座石台要直接进到里面，不要再停在「开始这一场」或能力说明。

## 决策

- 采用：`/paths?gate=` 顶部是两条细进度，「阅读 n/N 场」「交付 n/M 项」。下面各铺一条石台路。
- 采用：点阅读石台立刻打开课文。点支线石台同样立刻打开课文。
- 采用：点交付石台只打开这一份自评，地址是 `?gate=&deliver=`。勾选仍是自评，文案保持「这些勾选是自评，没有测试记录不算验证通过」。
- 采用：`?boss=core` 直接是核心挑战的当次任务，前面不再加一段说明。
- 不采用：不再使用 `?scene=`，也不再在这一页放「开始这一场」或能力目标。`gateVerify.ts` 和 `gateCleared` 保留，浮动关卡上的验证计数这次不动。

## 改动清单

| 路径 | 变更 |
| --- | --- |
| `web/src/pages/PathPage.tsx` | 阅读、交付、支线都从石台直接进入；没有 `deliver` 参数时不再误开第一份交付 |
| `web/src/styles/_reading.scss` | 进度条改成名称在左、分数在右、细条在下 |

`params.get('deliver')` 为空时 `Number(null)` 是 `0`，会把第一份交付当成已选中。空参数要先判空，再转成数字。

## 验证

```bash
cd web && npx tsc --noEmit -p tsconfig.app.json
```

- 结果：`tsc` 退出码 0。
- 浏览器 `http://127.0.0.1:5175/#/paths?gate=g1`：进度为「阅读 2/8 场」「交付 0/3 项」，阅读 8 座、交付 3 座，没有「开始这一场」。
- 点交付第一座「四段职责」进入 `?deliver=0`，只有这一份自评和「回这一关」。回到图上仍是 11 座。没有点印章。
- `#/paths?side=fe`：直接是 9 座场次，没有介绍卡。`#/paths?boss=core`：直接是当次任务。
- 390 宽下关卡页没有横向溢出。
