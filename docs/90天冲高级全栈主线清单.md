## 1. 三个必须交付的作品（验收比课表重要）

### 作品 A · 全栈写路径（第 1～30 天结束必须可演示）

做一个「下单 / 改库存」类最小功能（可用内存库，但规则要真）。

| 验收项 | 过线标准 |
| --- | --- |
| 四层对齐 | 能指出按钮态、契约 type、事务、唯一约束各在哪一层 |
| 写成功 | 成功 = 不变量已提交，不是 200 字符串 |
| 并发 | 最后一件库存，两请求只有一成功，库存不为负 |
| 幂等 | 同一幂等键重试不双写；前端超时重试带原键 |
| 失败 UI | 400 / 409 / 5xx / 断网文案与草稿策略不同 |
| 证据 | 仓库 + README 演示步骤 + 3 张失败截图或测试名 |

对应必读（按顺序）：

1. `fs-four-layers` → `fs-page-feature` → `fs-write-ui` → `fs-frontend-done`
2. `fs-boot-chain` → `fs-write-invariant` → `fs-read-shape` → `fs-ship-bar`
3. 补刀：`http-methods`、`query-server-state`、`spring-transaction`、`idempotency`、`cookie-credential`（或会话相关课）

### 作品 B · 读路径与一致性（第 31～60 天）

在 A 上加「详情/列表」与一层缓存（可 Redis，也可本地 Map 模拟失效规则）。

| 验收项 | 过线标准 |
| --- | --- |
| 读形状 | 响应是用例要的 DTO，不是实体全量 |
| 新鲜度 | 能说明「这份读有多新」（缓存命中 / 穿透后回源） |
| 更新策略 | 写成功后删缓存（或等价失效），不双写空窗讲不清就不过 |
| N+1 | 列表接口无循环查；有查询次数对比（日志或测试） |
| 证据 | before/after 查询次数或耗时；一次「改价后读到旧价」的排错笔记 |

对应必读（按需抽，不必全章）：

- 数据库 / JPA：`jpa-session-nplus1` 及索引、事务隔离相关 3～5 课
- 缓存：旁路缓存、热点、大 key 相关课（以「删 vs 更新」为主）
- 读主线回头对照 `fs-read-shape`

### 作品 C · 异步与边界（第 61～90 天）

在 A 上加一种异步副作用（发站内信 / 记审计日志均可），用 **Outbox 或事务消息思路**（实现可简化，概念不能糊）。

| 验收项 | 过线标准 |
| --- | --- |
| 不双写空窗 | 业务库提交与「要发的消息」同事务落库，或等价可证明方案 |
| 消费幂等 | 重复投递不重复副作用；幂等键在可靠存储 |
| 限流/超时（可选加分） | 能说明拒绝超限 ≠ 下游已失败（对照 Sentinel 课） |
| 运维最小集 | 健康检查 + 结构化日志 + 一种延迟/错误指标（哪怕 Prometheus + 一行） |
| 证据 | 时序图（可手绘）+ 重复消费测试 + 一篇「若协调者挂了会怎样」短文 |

对应必读：

- `distributed-outbox`、`distributed-idempotent-key`、`distributed-cap`
- `mq-consume-idempotent-key`、`message-delivery`
- 选读：`sca-sentinel-intro` / `sca-sentinel-block`；Seata 只要求能说清边界，不要求上生产

## 2. 90 天日程（默认 3～5 年）

### 第 1～30 天 · 打穿主线

| 周 | 阅读重心 | 动手 |
| --- | --- | --- |
| W1 | 前端全栈主线 4 课 + `http-methods` | 定契约（路径/字段/type）；搭前端表单四种状态 |
| W2 | Java 全栈主线前 2 课 + `spring-transaction` | 校验 → 用例 → 仓储；事务测并发扣库存 |
| W3 | `fs-read-shape`、`fs-ship-bar`、`idempotency`、会话/Cookie | 幂等键 + 唯一约束；失败 UI 五分支 |
| W4 | 回看主线；工程实践里挑测试 2 课 | **作品 A 验收**；写「六件事」口述稿（前端 done + Java ship） |

**周检查：** 盖住笔记，10 分钟讲完一次下单的成功与四种失败。讲不利索 → 停新课，只补洞。

### 第 31～60 天 · 读、库、缓存

| 周 | 阅读重心 | 动手 |
| --- | --- | --- |
| W5 | 数据库索引 / 约束 / 事务隔离（各 1～2 课） | 列表+详情；用测试锁住响应形状 |
| W6 | JPA N+1 与会话 | 消灭 N+1；留下查询次数证据 |
| W7 | 缓存旁路与失效 | 写后失效；制造并修好「读到旧价」 |
| W8 | 浏览器性能或网络课 2～3 节（按弱项） | **作品 B 验收**；补一篇排错笔记 |

**周检查：** 画出「写成功 → 缓存 → 下一次读」时序；标出会脏读的一步。

### 第 61～90 天 · 异步、分布、像高级一样收尾

| 周 | 阅读重心 | 动手 |
| --- | --- | --- |
| W9 | Outbox、消息投递、消费幂等 | 落 Outbox 表或等价；消费者幂等 |
| W10 | CAP + 幂等键分布式课；Sentinel 选读 | 故障注入：重复消息、进程中杀 |
| W11 | 工程实践：日志、配置、发布相关 3 课 | 指标/健康检查；README 变成「别人能跑」 |
| W12 | 薄弱章回炉；AI 线可选 2～3 篇应用向 | **作品 C 验收**；模拟面试 45 分钟（自录或找人） |

**周检查：** 回答「分区时这笔写是成功、失败还是等待？恢复后如何收敛？」——答成产品口号则不过。

## 3. 阅读纪律（避免 719 课陷阱）

1. **每章最多深挖 3～5 课**，其余当目录，用到再查。  
2. 每课只留下三行笔记：`错念` / `正确机制` / `我如何验证`。  
3. 同一错念第二次出现 → 写成作品里的自动化测试，不只收藏。  
4. React/Vue 原理站（Mastery Lab）按需跳转，**不另开 90 天平行计划**。  
5. AI 线：有余力再走「应用开发」小环（调模型 → 检索 → 评测），不占主线预算超过每周 2 小时。

## 4. 第 90 天总验收（自评表）

全部勾上才算「这 90 天达标」，与是否「已被公司定为高级」无关。

- [ ] 作品 A/B/C 均有可克隆仓库与演示步骤  
- [ ] 不看资料讲清：校验、事务、幂等、缓存失效、Outbox、一种限流/超时语义  
- [ ] 至少 3 篇带时间线的排错笔记（现象 → 假设 → 证伪 → 修复）  
- [ ] 至少 1 次对外讲述（组会 / 博客 / 录屏均可）  
- [ ] 能指出本课库**不能代替**的两件事（例如：真实 On-call、组织推动）并写出下一步计划

## 5. 刻意不做

- 不追求课表 100% 打卡  
- 不并行「再学一门新框架」替代作品验收  
- 不把 Seata / 微前端当 90 天主线（需要时再开专题月）  
- 不把「看完分布式章」写成简历，只写「做成了什么、如何验证」
