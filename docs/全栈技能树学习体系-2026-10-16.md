## 1. 一条学习怎么走完

```text
星图上看到可以开始的一项
  -> 打开这项的第一篇未读课（课始终可开）
  -> 读完挂着的课，印章点亮，直接子项变为可以开始
  -> 这项若挂了关卡，去那一关做交付
  -> 本地检查通过，或那一关已交付：熟练度从「读完」变成「练过」
  -> 关卡 1 / 3 / 5 / 6 交付后，点亮对应称号
```

「下一项可以开始」发生在前置课读完时，不发生在考核之后。考核只加练过印记和称号。暗星表示还没走到，课仍可打开。

## 2. 分支与顺序

星图列序和前置以 `docs/技能树结构-2026-10-15.md` 为准：计算机基础 → 前端 → Java → 数据存储 → 中间件 → 分布式与高并发 → 工程与运维 → AI → 架构。组内从上到下。`allOf` 最多两个，只表示缺了它就读不懂。

报告把九列收成八条主干，**不挪节点**：

| 主干 | 收什么 | 星图上仍在 |
| --- | --- | --- |
| 通识 | 网络、算法、Linux、Git | 计算机基础 |
| 前端 | Web 入门到跨端，含双框架 | 前端 |
| 后端 | Java、缓存、消息、微服务组件、连接池、分布式 | Java、中间件、分布式与高并发 |
| 数据库 | SQL 与库 | 数据存储 |
| DevOps | Docker、Compose、Kubernetes、测试、持续集成 | 工程与运维 |
| 部署运维 | Nginx、CDN、对象存储、可观测、线上排查、错误预算、安全、密钥 | 中间件的接入组，以及工程与运维的观测和安全 |
| AI | 提示词到服务交付 | AI |
| 架构 | 聚合边界、服务拆分、架构决策 | 架构 |

DevOps 在这里指容器、测试和持续集成。部署运维指接入、观测、排查和安全。两条在报告里分开，星图列不拆。

## 3. 画面

| 看到的 | 条件 |
| --- | --- |
| 未走到 | 前置还没点亮 |
| 可以开始 | 前置已点亮，自己的课还没读完 |
| 正在点亮 | 当前场景里优先已读过一部分的那一项。同时只有一项。印章燃一下 |
| 读完 | 挂着的课都读过。没有自己的课时，全部前置已点亮 |
| 练过 | 已经读完，并且本地检查通过，或这项挂着的关已经交付 |

每项有阅读进度条。每一列有点亮条：有点亮的列标题带光，整列点亮后组块内侧发亮。减少动效时不播燃烧。

没有经验值，没有排行。练过不是认证。

## 5. 进度与改路

星图标题下实时给出：整树已点亮数、四枚称号、八条主干的已点亮和练过。

| 场景 | 建议 |
| --- | --- |
| 全图，一项都没读完 | 若已有正在点亮的项，写出它的名字；否则说明八条都还没点亮。不改场景 |
| 全图，已有点亮 | 指出完成度最低的主干。不改场景 |
| 选定的路被前置卡住 | 留在这条路，写出还走不到的项和缺的前置 |
| 选定的路能开始的都点亮了 | 建议下一条仍有暗星的路：浏览器应用 → Java 服务 → AI 应用。按钮才改 `skillScene` |

三条路仍只决定「正在点亮」从哪几步里挑。路外的印章不打暗。

## 7. 给下一模型

1. 先读本文、`docs/技能树结构-2026-10-15.md`、`web/src/data/skillCycle.ts`。
2. 改列或前置时先改结构文档，再改 `SKILL_VIEWS` / `LEARNING_SKILLS`。主干汇总在 `skillTrunkId`，不要为了报告去挪列。
3. 禁区：勿改 `gateCleared`；勿把已点亮、练过或称号写成认证；勿用考核锁课；勿把 Redis、消息队列、分布式一致绑回 MySQL；勿为没有课的词条造空节点。
